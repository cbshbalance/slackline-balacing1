# v23 1차 검증 기록

2026-09-05. 기준: cbsh/main `9602bf2`의 v21 실측 비동기 FWE 프리셋.
기존 로컬 v22 수정은 변경하거나 이 커밋에 포함하지 않았다.

## 동일 입력 비교

PC에서 OpenCR와 같은 `control_core.h`를 네이티브 C++로 컴파일했다.
v21 원본 제어기와 C++ 코어에 매 주기 같은 측정값을 주고, C++ 출력으로
v21의 MuJoCo 물리계를 구동했다. A, 유지각, 프로파일 위치/속도, 상태를 비교한다.
즉 아래 결과는 MCU 실시간 실행 시험이나 실물 서보 시험이 아니다.

| 초기 beta / phi [도] | 이득 | 발목 잡음 [도] | 시험 결과 | 접기 횟수 |
|---|---:|---:|---|---:|
| 0.5 / 0 | 9.5 | 0 | 12초 유지, 불일치 없음 | 37 |
| -0.5 / 0 | 9.5 | 0 | 12초 유지, 불일치 없음 | 37 |
| 1 / -1.64 | 9.5 | 0 | 12초 유지, 불일치 없음 | 34 |
| 0.5 / 0 | 9.5 | 0.05 | 12초 유지, 불일치 없음 | 74 |
| 0.5 / 0 | 3.8 | 0 | 6.105초 낙하, 불일치 없음 | 28 |
| 0.5 / 0 | 7.6 | 0 | 12초 유지, 불일치 없음 | 19 |
| 0.5 / 0 | 11.4 | 0 | 7.340초 낙하, 불일치 없음 | 39 |

200Hz, seed=0. 비교 허용 오차는 1e-7도이며 실제 최대 위치 차이는 4.13e-13도 미만.
이득 11.4에서는 접기 타임아웃 1회가 있었다. 동일 입력 계산 일치는 확인했지만,
넓은 이득 범위의 안정성이나 모든 측정·상수 오차에 대한 강건성을 확인한 것은 아니다.
실물 펌웨어는 접기 타임아웃에서 토크를 끈다. 이 안전 동작은 v21의 REST 진행과 다르다.

## 기동과 기록

- 신호에 상대적인 놓기 시점 -100, 0, +100, +200ms: 네 조건 모두 12초 유지, 불일치 없음.
- 손이 자세를 구속하는 단순 모형이며 실제 손 접촉·부저 지연·사용자 반응을 검증하지 않는다.
- C++ 시작 상태기계와 원시 재생 회귀 테스트 6개 통과.
- 초기화 이벤트의 힙각을 기록한다. 설정/초기화 누락, 샘플 누락, 출력 큐 누락,
  FAULT 구간을 정확히 재현했다고 판정하지 않는다.

## 빌드와 화면

- OpenCR 1.5.3 / Dynamixel2Arduino 0.8.1 빌드 통과.
- flash 98,900 bytes (12%), 전역 RAM 51,832 bytes.
- Chrome: 샘플 이동, 스크럽, 분석, 새 2초 시뮬레이션 수신 시험.
- 1440x1080, 1920x1080, 390x844: 가로 넘침 없음, 3D 캔버스 비어 있지 않음,
  샘플 변경 시 자세 변경 확인. 브라우저 예외 없음.
- USB 연결, 보드 업로드, 실제 200Hz 주기/서보 추종/균형 시험은 수행하지 않았다.

## 재현과 다음 확인

실행 명령은 README의 시험 절을 따른다. 전체 결과/설정/소스 SHA-256은
`reports/validation.json`, `reports/startup.json`, 개별 JSON/CSV에 다시 생성된다.
개인 실험 로그와 빌드 결과는 Git에 넣지 않는다.

실험실에서는 핀·센서 부호·영점 확인 후 dry 상태에서 판단을 기록한다.
그다음 지지한 상태에서 서보 목표와 실측 힙각, dt_us, 통신 오류, 전류 한계를 확인하고
준비-카운트다운-신호-놓기 절차를 반복한다. 코어 일치만으로 실물 균형 성공을 선언하지 않는다.
