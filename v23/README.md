# v23 - 어름이 검증실

v21 실측 비동기 FWE를 기준으로 새 OpenCR 펌웨어와 같은 입력의 결과를 비교한다.
실제 센서 자세를 그리는 v22의 Three.js 트윈과 측정 분석 함수를 재사용한다.
기존 v21/v22 파일은 수정하지 않는다. 발표 연출보다 원시 기록과 샘플 검토가 우선이다.

## 실행

저장소 루트에서:

```powershell
python -m pip install -r v23/requirements.txt
python v23/validation.py --suite
python v23/server.py --port 8230
```

브라우저: http://127.0.0.1:8230
`run_v23.bat`로도 실행할 수 있다. 포트가 사용 중이면 `--port 8231`처럼 바꾼다.
첫 검증 실행은 C++ 공유 라이브러리를 빌드하므로 시간이 걸린다. 도구·빌드·개인 로그는 Git에서 제외한다.

## 구조와 검증 경계

- `firmware/v23_controller/control_core.h`: PC와 OpenCR가 **같은 파일**을 컴파일한다.
  각도는 도 단위. 200Hz, 25ms 차분, EMA 계수 1/7, 누적 유지각, 사다리꼴 프로파일,
  도착 오차 0.5도, REST 60ms를 v21 코드의 순서까지 맞췄다. A 자체의 추가 필터/자동 트림 없음.
- `native.cpp`, `core.py`: C++ 코어의 ctypes 어댑터. 별도 Python 제어기 복제품을 시험하지 않는다.
- `validation.py`: v21의 실측 프리셋과 원본 물리 엔진을 읽는다. 같은 측정 샘플에 대해
  A, 유지각, 프로파일 목표/속도, 상태를 비교한다. 실제 물리 구동은 새 C++ 출력이 맡는다.
  JSON에 입력 설정, 소스 SHA-256, 최초 불일치, 낙하 여부, 모든 샘플을 남긴다.
- `server.py`: 원시 USB 로그, 설정/이벤트 저장, v22 CSV 가져오기, C++ 재계산, 분석 API.
- `static/`: 트윈, 두 평면, 타임라인, 샘플 전후 이동, 이벤트 점프, 파일 가져오기/내보내기.

**코어 일치와 실제 서보 일치는 다르다.** 시뮬에는 v21의 내장 PD 모형이 있고, 실물은 XM430의
내장 위치 제어기가 동작한다. 새 펌웨어는 코어의 위치 레퍼런스를 200Hz로 보내고 서보의
추가 프로파일을 끈다. 실제 추종·처짐·부저 타이밍은 실험실에서 확인해야 한다.
펌웨어는 접기 타임아웃에서 정지한다. v21은 그때 REST로 계속 진행하므로 이 상황은 의도적 차이다.

기본 상수는 v21 실측 버튼의 **모델 상수**다(P2R 0.412218, wphi 0.607864 등).
8/22 실물 상수(P2R 0.4285, r -1.506, lambda 5.44)와 자동으로 섞지 않는다.
실물 상수/속도 가중치 선택은 기록 가능한 명시적 변경으로 한다.

## 재생과 측정

`baseline.json`을 열고 재생하거나 한 샘플씩 이동한다. 시간, 자세, 두 평면, 수치가 같은 행을 본다.
JSON 세션은 원시 채널, 설정, 이벤트, 비교 결과를 함께 보존한다. CSV/raw.txt도 읽을 수 있지만
설정·시작 이벤트·샘플이 없는 기록은 정확한 펌웨어 재현으로 판정하지 않는다.
USB 기록은 `logs/<시각>_<고유번호>.raw.txt`에 즉시 남고, 연결 해제 때 JSON/CSV를 함께 저장한다.
`seq` 누락 또는 재부팅이 있으면 비교 유효성을 해제하며, 명시적 초기화 이벤트 후 다시 시작한다.
기본 예측점은 v21의 감쇠 포함 행렬 P를 그대로 사용한다. 모델 없이 속도 가중치를 수동 변경하면
`prediction_kind=coefficient_projection`으로 구분하고 A 기준선의 진단용 투영만 표시한다.
이 경우 원위치 평면의 물리적 안정모드선은 추측해서 그리지 않는다.
기존 v22의 P2R/람다/진동 적합은 구간 지정 후 사용할 수 있다. 반환된 사용 점·식·잔차는
현재 결과 영역의 구조화된 데이터로 확인한다. 상세 적합 시각화는 기존 v22 화면에 남아 있다.

## 실물 시작 절차 (실험실 확인 대기)

1. OpenCR + AS5047P 두 개(CS 10,9) + XM430 ID 1, DXL 1Mbps를 사용한다.
   현재 하드웨어가 다른 경우 그대로 업로드하지 않고 핀/부호를 확인한다.
2. 부팅은 **토크 OFF / dry ON**이다. USB 연결만으로 영점·모터 명령을 보내지 않는다.
3. 매달림 영점은 토크 OFF에서 `zero_hang`을 양쪽 정착 후 두 번 보낸다.
   phi/ank 원각의 원형 평균, 힙 위치 평균을 저장하고 ank에 +180도를 한 번 적용한다.
   `zero`는 현재 자세를 직접 영점으로 잡는 별도 벤치 명령이다. 두 방식을 혼용하지 않는다.
4. 세운 뒤 채널별 부호와 트윈 자세를 확인한다. phi_offset/ank_offset 조정은 정지 중에만 한다.
5. `prepare`: 현재 힙각 유지, 속도 필터 초기화, 측정 시작. 정지 0.5초와 작은 A가 확인되면 READY.
   **현재 A를 0으로 만드는 트림은 하지 않는다.**
6. `go`: 2초 카운트다운. 준비 조건이 깨지면 취소. 마지막 신호와 동시에 제어가 활성화된다.
   부저는 OpenCR BDPIN_BUZZER의 비블로킹 tone을 사용한다. 신호에 맞춰 놓는 절차는 실물 반복 시험 대상이다.
7. dry에서 판단 방향을 본 뒤, 지지한 상태에서 `dry 0`, `prepare`, `go`로 실제 구동한다.
   dry 상태에서는 트윈은 실측 자세를 그대로 표시하며 가상으로 접힌 척하지 않는다.
8. `stop`은 현재 자세 유지, `x`는 토크 OFF다. GUI는 줄바꿈을 붙여 보낸다.

상태: DISARMED(0), PREPARING(1), READY(2), COUNTDOWN(3), RUNNING(4), FAULT(5).
SPI parity/error, DXL 통신, 제어 주기 누락, 한계각, 접기 타임아웃을 기록/정지 사유로 둔다.
USB 출력은 OpenCR 1.5.3의 `CDC_Itf_Write` 단발 호출을 사용한다. 일반 Serial.write의
최대 100ms 재시도를 사용하지 않으며 큐가 넘치면 샘플을 버리고 tx_drop/seq로 드러낸다.

## 시험

```powershell
python v23/tests.py
python v23/validation.py --suite
python v23/validation.py --startup
python v23/e2e.py
```

브라우저 시험은 Playwright와 설치된 Chrome을 사용한다.
시험 도구는 `python -m pip install playwright pillow`로 설치한다.
`--startup`은 손이 자세를 구속한다는 단순 모형에서 신호 전후 놓기 시간을 바꾼다.
실제 손 접촉/사람 반응 모형이나 시작 성공률 보장은 아니다. 시작 상태기계는 별도 C++ 시험으로 검증한다.

OpenCR 빌드: ROBOTIS OpenCR 1.5.3 + Dynamixel2Arduino 0.8.1,
`arduino-cli compile --fqbn OpenCR:OpenCR:OpenCR v23/firmware/v23_controller`.
업로드 및 실물 균형 시험은 이 사무실 작업에서 수행하지 않는다.
