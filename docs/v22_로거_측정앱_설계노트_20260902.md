# v22 로거·측정 앱 — 설계 노트 (2026-09-02, Claude Code)

> 사용자 요청(9/2): "v21 코드 그대로 v22 폴더를 만들고 로거 기능을 추가. 그동안 여러 사람이 펌웨어를 만들어 왔고 결과도
> AI 분석으로만 들어서, **현재 펌웨어가 어떤 값을 어떻게 재고 걸러서 어떤 구간으로 어떤 적합을 해 값을 내는지 모르겠다.**
> 기본 기록·실시간 모니터링부터 세우고, 콘솔 명령은 앱 버튼으로, 측정 결과는 그래프로 보며 **어떤 영역이 어떻게 선택되어
> 어떤 적합 과정을 거쳤는지 검토**할 수 있는 앱. 기본 화면은 v21 예측점 평면 전체화면처럼 한쪽에 애니메이션, 옆에 두 평면,
> 옆에 원본값, 기록·재생·그래프." 폴더 이름 `v22_logger` 승인.

## 1. 결정 사항

| 결정 | 이유 |
|---|---|
| v21_pres 를 통째로 복사, 발표 화면은 `/pres` 로 보존, 측정 앱은 새 페이지 `/` | "v21 코드 그대로" + 발표 기능(오버랩·씬체인)이 측정 화면을 어지럽히지 않게 |
| **원시 열에서 앱이 다시 계산** (α·β·속도·Â·예측점), 펌웨어 열은 `_fw` 로 나란히, Δ 표시 | 사용자 핵심 불만 = 펌웨어가 무엇을 계산하는지 모름. 같은 원시값에서 앱이 낸 값과의 차이가 곧 "펌웨어가 다르게 한 것" |
| 분석 도구는 모두 `steps/used/overlay/curves` 를 반환 | "어떤 영역·어떤 점·어떤 식" 이 화면에 그대로 나와야 검토가 된다 |
| 데이터 정본은 서버(Python·numpy)가 들고, 브라우저는 뷰 | 오프라인 정본 스크립트(p2r_fit·lambda_fit·r_fit)와 같은 수식·라이브러리로 계산. JS/Python 이중 구현 회피 |
| 바이너리 프레임(float32 열우선) 스트리밍 | 200 Hz × 30 열 × 수십 분도 브라우저에서 즉시 스크럽 |
| 3D 트윈은 브라우저가 각도로 직접 구동 (MuJoCo set_pose 경유 안 함) | 지연 최소, MuJoCo 없는 PC 에서도 동작. 평면 상수만 시뮬에서 읽는다 |
| 연결하면 자동 기록 (`logs/<시각>_auto`), 「새 파일」로 나눔 | "기본적인 기록 기능" — 잃어버리는 데이터가 없어야 한다 |
| 명령 팔레트는 `commands.json` 데이터 | 펌웨어가 바뀔 때 코드 무변경 (v21 씬 체인과 같은 사상) |
| FakeSource (파일 재생·합성 신호) | 장치 없이 개발·E2E·리허설. 로봇 없이도 앱을 검토할 수 있다 |

## 3. 구조

```
브라우저 (logger.html + lg_core/3d/plane/chart/panels.js)
   │ WS /ws2  JSON 명령 ↑ · 바이너리 ds_full/ds_append + JSON aux/link/console/analysis ↓
LoggerHub (server.py)
   ├─ LineSource: SerialSource(pyserial) | FakeSource(파일 재생·합성)
   ├─ LineSink   : '# D,…' 헤더 채택, D/R/F/E/기타 분류
   ├─ Recorder   : logs/<이름>.csv .trials.csv .folds.csv .events.csv .raw.txt (hangcal_logger 규약)
   ├─ Dataset    : 원시 열 + 파생열 (인과 파이프라인은 append 마다, 평활은 꼬리 갱신)
   └─ analysis   : stats / linfit / p2r / lambda / trials / phi_eq / osc / boundary / sysid
SimServer(v21, /ws, /pres) — MuJoCo 있을 때만. 평면 상수(P, r, slopeA0, sCoM)를 허브에 준다.
```
