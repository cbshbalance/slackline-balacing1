## 1. v21 이 무엇인가

**v19_state 를 확장한 종합 발표 시뮬레이터.** 세 가지를 더한다.

| # | 기능 | 왜 |
|---|---|---|
| **①** | **평면에서 마우스로 상태 집기** — 평면 위에서 마우스를 움직이면 로봇이 그 상태의 자세로 표시되고, **클릭하면 그 상태에서부터 v19 물리로 움직이기 시작** | 비전공자에게 안정모드/불안정모드를 **직접 보여주며** 설명. 실측 ②(안정모드선 찾기)를 화면에서 미리 시연 |
| **②** | **실사 영상/사진 오버랩** | 시뮬 자세와 실물 자세를 겹쳐 대조 |
| **③** | 발표용 화면 구성 정리 | 씬 이동, UI 숨김 등 |

**구조는 라이브 서버 유지** (v19_state 방식: Python + MuJoCo + WebSocket).
노브를 돌리면 즉시 반응하는 것이 이 도구의 값어치이므로, 미리 구운 궤적으로 가지 않는다.

> ⚠ **이름 충돌 주의.** 사용자가 말하는 "v20"은 **다른 컴퓨터에 있는 별개 시뮬**
> (평면 → 마우스 → 로봇 자세)이다. 레포의 `v20_sim/` 은 **전혀 다른 것**
> (2026-07-31 배치 비선형 시뮬)이고, 그 전략 판정은 이미 철회됐다(문서 26).

### 3-2. 평면의 정의 — v21 의 핵심

| | |
|---|---|
| α | 하체 각 (연직 기준) |
| θ | 상체 각 = α + δ |
| δ | 힙 접힘각 (= θ − α) |
| φ | 줄(크랭크) 각 |
| **β** | **무게중심 각 = P1R·α + P2R·θ**, P1R = 0.5878, P2R = 0.4122 (합 1) |

**위험도** `A = w·[φ, β, φ̇, β̇]`, w = [0.6079, 1.0, 0.1027, 0.1689]

**예측점** = (β + β̇/λ, φ + φ̇/λ), λ = 5.9219 /s

두 평면:
- **원위치 평면** (β, φ) — 안정모드선 기울기 `r = −1.6445`
- **예측점 평면** (β_pred, φ_pred) — A=0 선 기울기 `slopeA0 = −1.6451`

**★ 둘은 같은 선이다** (0.04% 차이). 즉 **A = 0 ⟺ 예측점이 안정모드선 위에 있다.**
그리고 `w = [−1/r, 1, −1/(rλ), 1/λ]` — w 는 r 과 λ 만으로 결정된다 (0.035% 일치).

### 3-3. 실기 파이프라인은 한 묶음

| | 실기 펌웨어 | 시뮬 기본 |
|---|---|---|
| 제어주기 | **200 Hz** | 500 Hz |
| 속도 기저차분 | **25 ms (5샘플)** | 2 ms |
| 속도 EMA | **τ ≈ 28 ms** | τ = 10 ms |

**⚠ 셋을 따로 켜면 안 된다.** 500 Hz 에 25 ms 차분만 얹으면 **13스텝 차분**이라는
실기에도 시뮬에도 없는 잡종이 되고, 거기서만 나오는 늦은트리거·과접기를
실기 현상으로 오인한다. **이 실수로 하루를 썼다** (README 「철회된 결론」 참조).

UI 체크박스 **★ 실기 파이프라인** 이 셋을 함께 전환한다. 빨간 버튼은 켠 채로 시작.

## 4. v21 신규 기능 — 설계 노트

### 4-1. 평면 → 상태 (마우스 집기)

**좌표 변환이 아주 간단하다.** 놓기 시험은 **속도 0, δ = 0** 이 자연스러운 설정이고,
δ = 0 이면 θ = α 이므로

```
β = P1R·α + P2R·θ = P1R·α + P2R·α = α        (P1R + P2R = 1)
```

**즉 β = α.** 평면 위의 점 (β, φ) 가 그대로 `alpha0 = theta0 = β`, `phi0 = φ` 가 된다.

**서버 명령이 이미 있다:**

```js
send({cmd:"x0", phi0: <φ>, alpha0: <β>, theta0: <β>});
send({cmd:"reset"});     // reset() 은 위치만 세팅, 속도는 0 — 놓기 시험 그대로
```

기존 슬라이더 `sA0`/`sP0` 가 이미 이 경로를 쓴다 (`index.html` 611~612행).

**구현 방향**
- `drawPlane()` 의 `X(b)`, `Y(f)` 가 상태→화면 변환. **역변환**을 만들면 마우스 좌표 → (β, φ)
- **hover**: `cmd:"x0"` + `cmd:"reset"` 을 보내고 3D 만 갱신 (물리 정지 상태)
- **click**: `cmd:"run"` 으로 물리 시작
- 마우스가 움직일 때마다 리셋을 보내면 트래픽이 많다 → **throttle**(예: 50 ms) 또는
  hover 전용 경량 명령(`cmd:"pose"` — 리셋 없이 qpos 만 세팅)을 새로 만드는 편이 낫다

**예측점 평면에서는 hover 가 부정확하다.** 예측점은 속도를 포함하는데 놓기 시험은 속도 0 이라
예측점 = 원위치가 된다. **원위치 평면에서만 hover 를 켜거나**, 예측점 평면에서는
"속도 0 가정" 을 화면에 명시할 것.

**교육적 시나리오** (이게 이 기능의 목적)
1. 초록 선(안정모드선) **위**를 따라 마우스를 움직이며 클릭 → 발산 없이 흔들리다 잦아든다
2. 선에서 **벗어난** 곳을 클릭 → 한쪽으로 넘어진다
3. → "이 선이 안정모드선이고, 실측 ②가 바로 이것을 실물에서 찾는 것"

### 4-2. 실사 오버랩

**`presentation/match.html` 이 이미 "실사 오버랩 매칭 도구" 다.**

**새로 만들지 말고 이걸 먼저 읽을 것.** v19_state 의 3D 뷰에 이식하는 것이 ②의 실체다.

## 6. 작업 규칙

1. **코드를 고치기 전에 반드시 묻는다.** 이해하지 못한 수정이 쌓이면 나중에 못 되돌린다.
2. **원본을 건드리지 않고 실험한다.** 파라미터 스윕은 `/tmp` 에 사본을 만들어 거기서.
3. **주장하기 전에 잰다.** 이 프로젝트는 "그럴듯한 설명"으로 여러 번 틀렸다.
4. **틀렸으면 문서에 철회를 남긴다.** README 「철회된 결론」 표가 그 형식이다.

### 이미 밟은 함정 (반복 금지)

- **A 는 `control_step` 이전 값으로 볼 것.** 접기가 시작되면 δ 가 곧바로 β 를 바꿔
  A 가 한 스텝만에 떨어진다. 이후 값으로 보면 전부 헛트리거로 오판된다.
- **실기 파이프라인 셋(200 Hz / 25 ms / τ30 ms)은 한 묶음.** 따로 켜면 잡종.
- **'힙 가동률'을 `phase != IDLE` 로 세지 말 것.** REST 대기가 포함된다.
- **단발 외란 시험으로 순위를 매기지 말 것.** 킥 위상에 좌우돼 비단조적 결과가 나온다.
- **σ_A 잡음 바닥은 가진이 있는 상태에서 잴 것.** 정지 상태에서는 항상 0 이 나온다.
- **접힌 자세를 초기조건으로 던지지 말 것.** 정적 평형이 아니라 놓자마자 가속한다.

### 연구의 성격

고등학생이 **정성적 추론**으로 AI 의 도움을 받아 역학 문제를 풀고 로봇을 제어하는 연구다.
대학원 수준의 제어이론·수식은 목표가 아니다. 모드분석까지는 필요해서 했고,
그 이후는 **상태공간과 예측점 평면**이라는 도구 위에서 정성적 추론으로 밀고 나간다.
**v21 은 그 도구를 남에게 보여줄 수 있게 만드는 작업이다.**
