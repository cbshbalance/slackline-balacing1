# 61. 접기 스파이크 재검증 — "물리" 판정 유지 + 메커니즘 서술 정정 (2026-08-19, Claude Code)

> 사용자 질문: "스파이크가 버그가 아니라 물리라는 얘기를 다시 검증해 보자.
> 스파이크 때문에 튀는 게 **정확히 −β에서 +β로** 반전할 수가 있나?"
> 방법: ★★실측 프리셋과 동일 조건(지터 0) 8 s 헤드리스 재계측, 5 ms(200 Hz)마다
> control_step **이전** 상태 기록 (문서 55 함정 준수). 코드 `scratchpad/spike_verify.py`
> (v21_pres 무변경 — 규칙 2).

## 1. 결론 세 줄

1. **"버그 아님·물리 맞음" 판정은 유지·강화된다.** β 자체가 MuJoCo 질량가중 CoM과
   최대 0.03 mm 이내로 일치(접기 중 포함) — 부호 오류가 낄 자리가 없다.
2. **그러나 "정확히 −β→+β 거울 반전"은 아니다.** 79건의 반전 전후 비율은 −1에 몰리지 않고
   중앙값 −1.50, IQR [−3.01, −0.76], 범위 [−12.6, −0.08]로 산포. '정확 거울'(−1±0.05)은 5%뿐.
   표시 부호 버그였다면 비율이 정확히 −1로 몰렸어야 한다. 화면에서 가끔 대칭처럼 보이는 건
   (예: −1.02°→+1.04° 실재) **빠른 0 통과가 5 ms 샘플에 우연히 대칭적으로 걸린 것**이다.
3. **문서 59의 메커니즘 문장 한 줄은 정정이 필요하다.** "접기 중 δ̇가 β̇ = P2R·δ̇로 들어가고"는
   방향이 틀렸다 — 그 직접 항만이라면 스파이크는 **반대쪽**으로 튀었어야 한다(아래 §3).
   실체는 **무게중심 보존 반작용**: β̇ ≈ −kFold·δ̇ (등고선 미끄럼의 속도).

## 3. 메커니즘 정정 — 직접 항이 아니라 반작용이다

β̇ = α̇ + P2R·δ̇ 이므로 문서 59는 δ̇의 **직접 운동학 항**(+P2R·δ̇)을 원인으로 썼다. 계측 결과:

- fold 중 Δβ_pred 와 직접 항 P11·P2R·Δδ̇ 의 상관 = **−0.998** (같은 방향이 아니라 **정반대**).
- 직접 항을 β_pred에서 빼도 반전은 사라지지 않는다 (79→96건).
- fold(|δ̇|>50°/s) 중 β̇/δ̇ 중앙값 = **−0.289** ↔ −kFold = −0.352 (같은 부호·같은 자릿수;
  준정적 등고선 미끄럼 Δβ = −kFold·δ 의 시간미분. 유한시간 동역학 때문에 ~18% 작음).
- 무게중심 보존 검사: fold 중 h·β̇ 와 (ẋ_CoM − R·φ̇)의 상관 **0.982**;
  |h·β̇|max 591 mm/s, |R·φ̇|max 647 mm/s로 각각 크게 튀는 동안 |ẋ_CoM|max는 84 mm/s.
  → **접기는 발(Rφ̇)을 던지고, CoM이 못 움직이므로 몸(hβ̇)이 반대로 튀는 내부 교환**이다.
  (ẍ_CoM = −gφ가 접는 도중에도 성립한다는 권위문서 보존법칙 그대로.)

크기도 닫힌다: |δ̇|max 303°/s → |β̇| ≈ kFold·303 ≈ 107°/s → 예측점 기여 ≈ 107/λ ≈ 18°
↔ 실측 |β_pred|max(fold) = 17.2° (idle 최대 2.2°).

## 4. 조치

- 표시 정리(「접기 스파이크 정리」 체크박스)·판정 경로 등 **코드 변경 없음** — 판정은 그대로 유효.
- 문서 59 §1의 원인 문장을 이 문서 §3으로 갱신해 읽을 것 (정본 관계: 59 상태 + 61 정정).
- 발표 문답 대비 한 줄: *"접기 순간 예측점이 반대로 크게 튀는 것은 오류가 아니라,
  발을 던질 때 무게중심이 제자리를 지키느라 몸이 반대로 밀리는 반작용이 예측점(속도를 1/λ로
  환산해 더한 점)에 증폭되어 보이는 것"* — 오히려 CoM 보존을 눈으로 보여주는 재료가 된다.

## ★정정 (2026-08-20, 규칙 4 철회 기록)

사용자 확인 결과, **8/18의 원 관찰("참값 β가 반전한다")의 실제 원인은 로봇이 매달려 있는 상태에서
각도가 +180° ↔ −180° 로 래핑되며 생기는 표시 반전**이었다. 그 관찰을 "접기 β̇ 킥"으로 단정한
문서 59·61의 진단은 **원 관찰에 대해서는 틀렸다 — 철회한다.**

단, 본 문서와 59가 계측한 "접기 위상 한정 예측점 스파이크"(fold/REST 79건·idle 0건, 반전값
±수° 소각 영역, CoM 보존 검증)는 래핑과 무관하게 시뮬에 실재하는 별도 현상이며, 「접기 스파이크
정리」 체크박스는 그 표시 정리용으로 유효하여 유지한다. ±180° 래핑은 별도 문제로, 실기 로그
재생(E1)의 각도 자동 언랩으로 대응한다.

교훈: 관찰의 원인을 단정하기 전에 더 단순한 후보(래핑·표시 규약)를 먼저 소거할 것.
확신이 없으면 "모른다 + 후보 목록"으로 답한다.
