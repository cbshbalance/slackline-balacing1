# 줄타기 로봇 시뮬레이션(v19_sim) 전(全) 해설 — 학생용

> 2026-07-18. 고등학생이 처음부터 끝까지 따라올 수 있도록, v19_sim 시뮬레이션의
> 모든 구성 요소 — 로봇 파라미터, 운동방정식, 관성행렬, 모드 분석, 시뮬레이션 방법과
> 근사, 오차 원인과 반영 방법, FWE 상수와 그 결정 과정 — 를 순서대로 설명한다.
> 수식 유도의 완전한 판본은 정본 문서(커플링 물리 적용 완결본, 모드분석 첫걸음 학생용)에
> 있고, 이 문서는 "시뮬레이션에 실제로 들어간 것"을 빠짐없이 명료하게 잇는 다리다.

## 0. 큰 그림 — 세 개의 세계

이 연구에는 같은 로봇이 세 가지 모습으로 존재한다.

1. **종이 위의 로봇 (이론 모델)**: 연필로 풀 수 있는 선형 수식. 여기서 ε*, γ 같은
   닫힌형 공식이 나온다. 단순화(소각 근사, 마찰 무시 등)를 대가로 "왜"를 얻는다.
2. **컴퓨터 속의 로봇 (전물리 시뮬레이션, v19_sim)**: MuJoCo라는 물리 엔진이
   단순화 없이 비선형 강체역학을 통째로 수치적분한다. 여기에 실물의 지저분함
   (모터 관성, 마찰, 센서 잡음)을 하나씩 "주입"할 수 있다 — 즉 **이론과 실물 사이에서
   무엇이 문제를 일으키는지 하나씩 분리 실험할 수 있는 세계**다.
3. **책상 위의 로봇 (실물 '어름이')**: 최종 목표. 시뮬에서 배운 것들이 브링업
   체크리스트가 되어 실물로 넘어간다.

시뮬레이션의 존재 이유는 정확히 이것이다: 이론이 실물에서 안 맞을 때, 실물에서는
원인 후보 수십 개가 한꺼번에 얽혀 있어 무엇 때문인지 알 수 없다. 시뮬에서는
후보를 하나씩 켜고 끌 수 있다.

## 1. 로봇과 파라미터 — 숫자 카드

### 1.1 기하 (v19 재설계 실기 그대로)

```
알루 프레임: 400 × 600 × 1220 mm, 회전축 높이 1245 mm
줄(크랭크): 카본 사다리꼴 — 상단 피벗 두 개가 60 cm 벌어져 있고,
            빗변 50 cm 두 개가 내려와 10 cm 발축 바에서 만난다.
            수직 처짐 R = √(50² − 25²) = 43.3 cm   ← "진자의 반지름"
로봇: 하체 L₁ = 25 cm + 상체 L₂ = 40 cm (허리에 XM430 서보 1개)
```

### 1.4 좌표 규약 (한 번만 제대로 외우자)

```

α (알파)   : 하체의 절대 기울기 (오른쪽 +)
θ (세타)   : 상체의 절대 기울기 (오른쪽 +)
δ = θ − α  : 허리 접힘각 = 우리가 제어할 수 있는 유일한 관절
β (베타)   : 가중 무게중심 기울기 = (p₁α + p₂θ)/(M_t h)   ← "쓰러짐 변수"
             p₁ = m₁ℓ₁ + m₂L₁ = 0.156,  p₂ = m₂ℓ₂ = 0.110
무게중심 위치: x_CoM = Rφ + hβ   ← 이 한 줄이 연구 전체의 뼈대
```

⚠ 함정 하나: MuJoCo 안에서는 φ의 부호가 반대다(x_foot = −Rφ). 시뮬 코드에서는
`get_state()` 함수 딱 한 곳에서만 변환한다. 실물에서도 엔코더 방향 상수
(ENC_PHI_DIR)를 브링업 1단계에서 확정해야 한다 — 부호 실수는 이 연구 역사상
가장 자주 사고를 낸 범인이다.

## 2. 운동방정식 — 라그랑지안에서 행렬까지

### 2.1 라그랑지안이라는 방법 (개념만)

뉴턴의 F=ma로 세 몸이 얽힌 계를 풀려면 관절이 주고받는 힘(구속력)을 전부 추적해야
해서 지옥이 된다. 라그랑주 방법은 대신 **에너지**로 우회한다:

> L = T − V   (운동에너지 − 위치에너지)를 좌표 q = (φ, α, θ)로 쓰고,
> d/dt(∂L/∂q̇) − ∂L/∂q = (외부 일반화힘) 을 계산하면 운동방정식이 나온다.

구속력은 자동으로 사라진다. 유도 전체는 정본 문서에 있고, 여기서 중요한 것은
**결과의 모양**이다. 각도가 작다고 근사(sin x ≈ x)하면 다음 꼴이 된다:

> **M q̈ = G q + D q̇ + E τ**

네 개의 행렬이 각각 물리 하나씩을 담당한다.

### 2.2 관성행렬 M — "밀었을 때 얼마나 무겁게 반응하나"

숫자를 그대로 적으면 (단위 kg·m²):

```
        φ         α         θ
φ  [ 0.1453    0.0676    0.0476 ]     M[φ,φ] = M_tR² + I_r   ← 줄 관성 포함!
α  [ 0.0676    0.0417    0.0138 ]     M[α,α] = m₁ℓ₁²+I₁+m₂L₁²
θ  [ 0.0476    0.0138    0.0293 ]     M[θ,θ] = m₂ℓ₂²+I₂
```

- **대각 성분** = 각 좌표를 혼자 흔들 때의 관성.
- **비대각 성분(커플링)** = "φ를 가속하면 α와 θ도 끌려간다"는 연결 고리.
  예: M[φ,α] = R·p₁ — 발이 원호를 따라 가속하면 하체가 관성으로 뒤로 젖혀진다.
  **이 커플링이 연구의 심장이다.** 허리 접기가 발을 던질 수 있는 이유도,
  "분리가정(줄 따로, 몸 따로)"이 3~4배 오차를 내는 이유도 전부 여기에 있다.

### 2.3 중력행렬 G — 안정과 불안정의 좌석표

```
G = diag( −(M_tR + S_r)g ,  +p₁g ,  +p₂g )
       = ( −3.02 ,  +1.53 ,  +1.08 )
```

φ행만 **음수**다: 줄은 흔들리면 가운데로 돌아오는 **안정한 진자**(S_r 덕에 줄
자체 무게도 복원을 거든다). α, θ행은 **양수**: 몸은 기울수록 더 기우는
**역진자**. "안정한 진자 위에 올라탄 불안정한 역진자" — 이 대비가 계의 성격이다.

### 2.4 감쇠 D와 입력 E

- D: 마찰·감쇠. 이론 기본형은 D = diag(−c_φ, 0, −B_θ). c_φ는 상단 베어링 점성
  (실측 전 0), B_θ는 힙 점성.
- E = [0, −1, +1]ᵀ: 허리 토크 τ는 상체에 +, 하체에 −로 **반대로** 작용한다
  (작용-반작용). φ행이 0인 것에 주목 — **토크는 줄을 직접 못 민다.**
  줄을 움직이는 유일한 통로는 M의 커플링뿐이다. 이것이 "저구동(underactuated)"
  구조: 자유도 3, 입력 1.

## 3. 모드 분석 — 6차원을 숫자 하나로 줄이기

### 3.1 (φ, β) 축약

δ를 "우리가 정해서 넣는 입력(프로파일)"로 보면, 남는 자유 운동은 (φ, β) 두 개로
정확히 줄어든다(좌표 변환 J — 유도는 정본 문서). 이 2×2 계의 고유값을 구하면
운동이 두 "모드"로 갈라진다:

| 모드 | 수치 | 물리적 그림 |
|---|---|---|
| 안정 진동 모드 | ω_eff = 6.89 rad/s (주기 0.91 s) | 줄+몸이 함께 그네처럼 흔들림. 저절로 유지됨 |
| 불안정 모드 | λ_eff = 6.45 /s (**배가시간 107 ms**) | 무게중심이 발 위에서 벗어나 e^{λt}로 쓰러짐 |

배가시간 107 ms의 뜻: 아무것도 안 하면 넘어짐 성분이 **0.1초마다 두 배**가 된다.
사람 스케일은 0.2~0.3초 — 로봇이 작아서 두 배 이상 급하다. 이 숫자가 이후 모든
"시간 예산" 논의의 기준이다.

### 3.2 위험도 A — 상태 6개를 숫자 1개로

상태는 [φ, β, φ̇, β̇] 네 개(축약 후)지만, 그중 진짜 위험한 것은 불안정 모드에
실린 성분뿐이다. 선형대수의 좌고유벡터 w를 쓰면 그 성분만 뽑아낼 수 있다:

> **A = wᵀx = w₁φ + w₂β + w₃φ̇ + w₄β̇,  w = [0.646, 1, 0.102, 0.156]**

- w₂=1로 정규화해서 A의 단위는 "β 환산 각도". A=2°란 "지금 상태의 넘어짐 성분이
  β 2° 기울기와 같은 운명"이라는 뜻.
- 속도 성분(w₃, w₄)이 들어있는 이유: β=0이어도 β̇이 크면 넘어지는 중이다.
  A는 사실상 예측점(q + q̇/λ) 개념의 일반형이다(감쇠가 있으면 w가 4차원
  좌고유벡터로 일반화 — 7/11 이론).
- **A = 0 ⇔ 예측점이 안정모드선 위 ⇔ 접지 않아도 스스로 돌아온다.**
  그래서 FWE의 목표는 "β를 0으로"가 아니라 "**A를 0으로**"다.

## 4. FWE 메커니즘과 상수들 — 무엇이 어디서 왔나

### 4.1 한 사이클의 물리 서사

기울었다(A≠0) → **접는다**: 허리를 δf만큼 접으면 반작용으로 발이 무게중심 너머로
던져진다(커플링!) → **기다린다**: 이제 중력이 줄을 통해 몸을 되돌린다. 줄이 일하는
시간 → **편다**: 돌아왔을 때 허리를 펴면 접을 때와 반대 킥이 마무리를 한다.

### 4.2 사이클 맵 — 상수 두 개가 전부다

한 사이클(접기 T_f + 대기 T_w + 펴기 T_e + 휴지 T_rest = 0.27 s)의 전후를 이으면:

> **A⁺ = G·A⁻ − g·δf**

- **G ≈ 5.5 = "기다림의 비용"**: 사이클 시간 동안 A가 저절로 자라는 배율
  (e^{λ·0.27}). 아무것도 안 접으면 위험이 5.5배가 된다는 뜻.
- **g ≈ 0.19 = "접기의 권한"**: 접기 1 rad이 A를 깎아주는 양.
- **γ = G/g ≈ 29 = "환산 계수"**: A 1°를 한 사이클에 정확히 지우려면(A⁺=0)
  몇 도를 접어야 하나. δf = γ·A가 'deadbeat'(한 방에 소거).
- **ρ = 전략 노브**: deadbeat의 몇 %를 갈 것인가. δf = ρ·γ·A.
  이론이 주는 안전창: ρ ∈ (1−1/G, 1+1/G) ≈ (0.82, 1.18) 안이면 |A|가 매 사이클
  줄어든다(수축률 |1−ρ|·G).

⚠ 이름 주의: 정본 문서의 γ(x) = eˣ/B(x)는 **유한시간 과접기 계수**(다른 물건)다.
코드의 GAMMA_CYCLE(=G/g)과 혼동하지 말 것. 문서의 γ(x) 물리는 g를 수치로 계산할 때
그 안에 이미 녹아 들어가 있다.

### 4.3 상수가 결정된 3단계 (이번 연구의 핵심 줄기)

**1단계 — 이론 계산 (γ = 28.9):** 줄 질량(I_r, S_r)과 감쇠(c_φ)까지 포함한
행렬(§2)에서, "δ가 명령한 삼각 프로파일 그대로 움직인다"고 가정하고 선형 방정식을
수치적분해 G와 g를 얻는다. 검산: 줄을 무질량으로 놓으면 옛 공식 ε* = −h/(rR+h)가
기계 정밀도로 복원된다.

**2단계 — 실행 캘리브레이션 (γ* = 18.6):** 전물리 시뮬에서 사이클을 45회 돌려
(A⁻, δf, A⁺)를 기록하고 최소제곱으로 G*, g*를 다시 적합했더니 **g가 44% 더
강했다**(0.197→0.285). 왜? 결정 실험(§7)으로 확인한 결과, 몸의 물리는 이론이
0.16° 정확했고, 어긋난 것은 **서보가 실제로 실행한 δ(t) 파형이 명령한 삼각
프로파일과 다르기 때문**(시작 스냅, 링잉, 추종 잔차). 즉 γ*는 이론의 수정이
아니라 **"내 로봇의 실제 몸짓"에 눈금을 다시 그은 것**이다.
실물 절차: 로봇을 살짝 기울여 올리고 한 사이클 접게 하기 × 12회
(접기 세기를 3단계로 섞을 것 — 안 섞으면 δf ∝ A라서 G와 g가 수학적으로
분리 불가능하다).

**3단계 — 온라인 노브 (자가 갱신):** γ는 사실 진폭에 따라 변한다(큰 접기는
서보 속도 한계에 걸려 권한이 포화). 그래서 매 사이클의 (A⁻, δf, A⁺)를 재귀
최소제곱(RLS, 망각계수 0.9)으로 흘려 넣어 G, g를 **운전 중에 계속 갱신**한다.
"노브가 스스로 돌아가는" 버전. Kt 오차, 마찰, 기어 효율 같은 **구동 채널 오차**는
이 노브가 전부 흡수함을 확인했다.

### 4.4 나머지 FWE 상수들

| 상수 | 값 | 역할 |
|---|---|---|
| A_TRIGGER | 0.4° | \|A\|가 이보다 크면 접기 발동 |
| T_FOLD / T_WAIT / T_EXTEND / T_REST | 80/60/80/50 ms | 프로파일 시간표. 전체 0.27 s ≈ 배가시간 2.5개 |
| δ_max | 55° | 접기 상한(기구 한계) |
| Kp, Kd (프로파일 추종 PD) | 80, 1.3 | 명령 δ(t)를 서보가 쫓게 하는 전류식 PD |
| 관성 피드포워드 | τ += I_δ·δ̈_ref | PD 강성 의존을 줄여 실행 파형을 명령에 붙임 |

## 5. 시뮬레이션은 어떻게 돌아가나

### 5.1 두 겹의 시간 루프

```
0.5 ms  물리 적분 (MuJoCo): 비선형 강체역학 + 마찰 제약을 수치적분
2 ms    제어 루프 (500 Hz, 실물 펌웨어와 동일 주기):
        ① 센서 읽기  — 양자화·잡음 포함 (아래 §6)
        ② 상태 추정  — 칼만5 / 상보필터 / 발목 엔코더 중 선택
        ③ 제어 계산  — LQR: τ = −K·x̂  또는  FWE: 상태기계(접기/대기/펴기)
        ④ 서보 모델  — 전류 양자화 → Kt → 토크-속도 한계 → 기어 효율
        ⑤ 물리로 전달 → 0.5 ms × 4번 적분
```

MuJoCo 세계에는 실기 기하가 그대로 서 있다: 프레임, 사다리꼴 크랭크(질량 분포
실물대로), 발목 베어링, 허리 모터. 소각 근사 없음 — 로봇이 90도로 넘어가 매달려
흔들리는 것까지 그대로 계산된다.

### 5.2 이 시뮬을 믿어도 되는 근거 (검증 7항목, test_headless.py)

1. 크랭크 관성: MuJoCo가 기하에서 계산한 I_r vs 질량표 공식 — **0.1% 일치**
2. 6차원 선형화 고유값: MuJoCo 수치미분 vs 이론 행렬 — 상대오차 0.1% 미만
3. 자유 발산의 성장률 실측 vs λ_u — ±10%
4. LQR 폐루프 거동 재현 (스틱션 리밋사이클 포함 — §6)
5. FWE 반복 유계 재현
6. 파라미터 편차 강건성
7. 한 프레임 되감기(스텝백)의 **완전 결정론** (같은 상태에서 다시 돌리면
   비트 단위로 같은 미래) — 디버깅 신뢰성의 토대

### 5.3 시뮬레이션이 하는 근사 (정직한 한계 목록)

- 서보 전류 루프를 순간 응답으로 취급(실제 수 kHz 대역폭 — 500 Hz 제어보다
  훨씬 빨라 영향 미미).
- PRESENT_VELOCITY의 내부 필터 지연 미모델(양자화만 반영).
- 케이블 장력, 공기 저항, 프레임 유연성 무시.
- 모든 질량·관성 값은 실측 전 설계 추정치 — **수치 결론은 실측 후 갱신 대상,
  구조적 결론(무엇이 지배하는가)은 유지될 것.**

## 7. 시도와 결과의 연대기 — 이제 납득이 되는 순서로

§1~6을 알고 나면 아래 흐름이 자연스럽다.

1. **LQR+칼만이 전물리에서 즉사** → 원인 추적 → **armature 발견**(§6 표 1행).
   게인 설계 모델에 armature를 넣으니(servo_aware) 생존. 교훈: "오차는 뭉개지
   말고 행렬에 넣어라"(7/11 원칙)의 새 사례.
2. LQR이 서긴 서는데 **±13° 진동** → 원인 분리 → **기어 쿨롱 마찰**(f_hip=0 이면
   0.5° 수렴). 7/11 이론의 "스틱션 → 유계 리밋사이클" 예측 그대로.
3. **센서가 병목** → 사용자 아이디어(발목 엔코더, IMU 제거) 구현 → LQR 기준
   "줄을 탄다" 도달.
4. **FWE는 전 구성 발산** → 범인 후보를 하나씩 소거(추정 오염? 정착 대기?
   관측기 대역폭? 전부 아님) → **결정 실험**: 실제 δ̈(t)를 이론 선형모델에 그대로
   넣으면 MuJoCo와 0.16° 일치. **이론 무죄. 범인은 실행 파형 갭.**
5. → **γ 실행 캘리브레이션(γ*=18.6)** → 참상태 반복 FEW가 전물리 최초 유계.
6. 실센서에서는 아직 수 초 후 낙하 → **c_φ(줄 감쇠) 0.008 주입** → 30초/98사이클
   유계. 감쇠가 잔여 안정모드 진동을 죽여 사이클 산포의 먹이를 없앰
   ("감쇠는 아군" — 7/11 예측 적중).
7. 미지 모델오차 실험 → **오차 이분법 발견**: 구동 채널 오차(Kt·마찰·효율)는
   노브(γ*, 온라인 RLS)가 흡수, **관성·기하 오차(m₂·R·armature)는 못 흡수**
   (위험도 방향 w와 β 가중치 자체가 틀어지므로). 다만 후자는 실측(저울·자·
   복합진자·자유진동 적합)으로 ±5~10%까지 눌리며, 그 수준이면 대부분 생존.
   남은 아킬레스는 실측이 어려운 armature — 접기 로그의 τ vs δ̈ 회귀로 잴 수
   있다(다음 과제).
8. 결과 해석의 언어: 이 스케일의 FWE는 "깨끗한 수축"이 아니라 **천장(A*≈3°)
   아래의 유계 랜덤워크**다. 사이클당 실행 산포(±0.5°)와 트리거(0.4°)의 신호 대
   잡음비가 ~1이라, 생존은 확률적 탈출시간 문제가 된다. 오차는 천장을 낮추거나
   걸음폭을 키워 수명을 줄인다.

### 연구 서사와의 연결 (판정 기준)

우리의 질문은 "FWE가 LQR보다 센가"가 아니다. 시뮬 결과로 정직하게 말하면:
**성능 상한은 (전문가가 모델을 수술해 튜닝한) LQR이 높다.** 그러나 LQR을 세우는
데는 armature 규명·행렬 수술·K 전면 재계산이 필요했고, gain_scale 노브만으로는
아무것도 복구되지 않았다. FWE는 같은 상황을 **측정 몇 번과 노브 하나**로 복구한다.
"모델이 틀렸을 때 아마추어가 고칠 수 있는 제어 + 균형의 물리 직관을 드러내는 제어"
— 이 서사는 시뮬 실험 전체로 오히려 강화되었다.

## 8. 모델 → 시뮬 → 실물에서 빠트리면 안 되는 것 (체크리스트)

이번 과정 전체에서 실제로 사고가 났거나 날 뻔했던 항목만 모았다.

**규약·단위 (사고 다발 구역)**
- [ ] 각도 부호 규약을 문서 한 곳에 못 박고, 변환은 코드 한 곳에서만 (φ = −q_phi)
- [ ] 센서 단위 확인 — 실물 사례: 자이로 raw LSB를 deg/s로 오독해 16.4배 오차(7/02)
- [ ] 방향 상수 3종(ENC_PHI_DIR, IMU_DIR, MOTOR_DIR)은 브링업에서 실측 확정

**모델링**
- [ ] 단일 진실 소스(params_v19.py) — 값은 한 곳에만, 게인은 자동 생성(복붙 금지)
- [ ] "오차"와 "파라미터"의 구분: 안정창보다 큰 이동을 만드는 것(줄 관성, armature)은
      행렬에 정확히 넣어야 한다. 뭉개면 창을 벗어난다
- [ ] 모터는 토크원이 아니다: armature(N²J), 기어 마찰/점성(N², N배), 효율 비대칭,
      토크-속도 곡선까지가 "모터"다
- [ ] 정역학으로 안 보이는 항(armature)이 동역학을 지배할 수 있다

**시뮬레이션**
- [ ] 시뮬 자체를 검증하라 (관성 교차검증, 선형화 고유값 대조, 성장률 실측)
- [ ] 재현성(결정론)을 설계하라 — 같은 입력이면 같은 출력이어야 디버깅이 성립
- [ ] 현실화 요소는 하나씩 켜고 끌 수 있게 — 분리 실험이 시뮬의 존재 이유
- [ ] 제어기에게 "몰라야 할 것"을 감춰라(공칭 vs 플랜트 분리) — 이게 안 되면
      강건성 실험이 자기기만이 된다

**캘리브레이션·브링업**
- [ ] 실측 우선순위: m·ℓ(저울·자) → I(복합진자) → c_φ(자유진동 로그감쇠) →
      ω_eff 대조(조립 후 자유진동) → armature(접기 로그 회귀 or 데이터시트×N²)
- [ ] 캘리브 실험 설계에서 공선성 주의 — 같은 비율로만 바꾸면 두 상수를 분리 못 한다
- [ ] 게인은 점진 인가(gain_scale 0.3→1.0), 안전 전류 상한부터
- [ ] 추정기는 "정확도"가 아니라 "격렬한 구간의 강건성"으로 평가하라

## 9. 작은 용어 사전

| 용어 | 영어 | 뜻 |
|---|---|---|
| 유계 | bounded | 발산하지 않고 유한한 범위 안에 머묾. 0으로 수렴한다는 뜻은 아님 |
| 수렴 | converge | 시간이 가면 한 값(보통 0)으로 다가감 |
| 리밋사이클 | limit cycle | 수렴도 발산도 아닌, 일정 진폭으로 반복되는 진동 |
| 포획영역 | capture region / basin | 제어기가 회복 가능한 초기상태의 범위 |
| 저구동 | underactuated | 자유도보다 모터 수가 적은 계 |
| 좌고유벡터 | left eigenvector | 상태에서 특정 모드 성분을 "읽어내는" 벡터 (w) |
| deadbeat | deadbeat | 한 스텝(사이클) 만에 오차를 0으로 만드는 제어 |
| 반영 관성 | reflected inertia | 기어 너머의 관성이 기어비²로 커 보이는 것 (armature) |
| 캘리브레이션 | calibration | 모델을 고치는 대신 측정으로 눈금을 다시 긋는 일 |
| RLS | recursive least squares | 데이터가 올 때마다 최소제곱 적합을 갱신하는 알고리즘 |
| 랜덤워크 탈출시간 | first-passage time | 잡음 속 배회가 경계(천장)를 처음 넘는 데 걸리는 시간 |
