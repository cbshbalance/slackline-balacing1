## 2. A — 4단계 마감 (실측 반영) : 먼저, 작게

명세가 문서 56 §3G에 이미 있고 수용 기준도 확정되어 있어 가장 싸게 끝난다.

- **A1. 실측선 오버레이**: 입력칸 r·절편·λ (기본 λ=5.3, 문서 53) → 두 평면에 별색 실측선·트리거 띠,
  `w = [−1/r, 1, −1/(rλ), 1/λ]` 병기. β̂ 재구성에 P2R 실측 0.417 명시 (문서 57).
  drawPlane에 두 번째 선 세트 추가 — 클라이언트만 수정, 물리 불변.
- **A2. 실측 발목잡음 프리셋**: `sim_engine._measure`에 채널별 σ 확장 (real 키), 기본 0.223° (문서 54).
  ⚠ 베어링 교체 후 재측정값으로 갱신 예정이므로 **값은 입력칸/프리셋으로** (하드코딩 금지).
  이것만 sim_engine에 닿지만 잡음 주입 경로 확장이라 물리·제어 불변 — v19_state 동일 시나리오
  (잡음 0) 궤적 일치로 검증.
- 실측 ②(안정모드선) 수행 시 이 입력칸이 바로 "시뮬 예측 vs 실물 한 화면"이 된다 (문서 58 §4-5).

## 3. B — 씬 체인 데이터화 : 발표와 프로그램의 상호작용 축

발표(49·51)가 미확정이고 계속 바뀐다는 사실이 설계 요구사항이다. **씬 = 데이터, 순서 = 배열.**

- `scenes/chain.json` (신규): `[{id, 제목, 메모, actions:[...]}]`. actions는 기존 서버 명령·UI 조작의
  선언적 나열 (예: `preset_measured`, `overlap_seq`, `pose`, `camera`, `panel:hide`, `plane:focus`).
- 키: `[` `]` 씬 이동, 숫자키 직접 점프, `Space` 정지(기존). 씬 목록 사이드 패널(발표자용, H로 숨김).
- 초기 체인은 문서 49 §8-2 기준 3단계 서사(①역설→…→⑧실물)로 채우되 **순서 교체·삽입·삭제가
  JSON 편집만으로** 되게. 학생 토의 결과를 그날 저녁에 반영할 수 있는 구조가 목표.
- 기존 개별 기능(영상 시퀀스·크로스페이드·모프·키네마틱 시연·ε* 작도)은 전부 액션으로 호출 가능하게
  래핑만 한다 — 새 연출 없음.

## 4. C — 포털 : "연구 여정의 지도"이자 입구

v10의 버전 네비게이션(v1~v10 버튼)을 전체 연구로 확장한 입구 화면.

**제안 구조** — v21 서버가 겸한다 (서버 신설 없음):

- `server.py`에 `/portal` 라우트 + 선별 폴더 read-only static 마운트
  (`v1_*`~`v11_small`, `v16~v18`, `presentation`, `deploy` 의 index.html 계열만. `tmp/`·미디어 대용량 제외).
- 순수 JS 시뮬(v1~v10, v11_small, v16~v18, presentation, deploy)은 **포털에서 바로 열린다.**
- 서버형(v19_sim·v19_state)은 포트가 다르므로: 카드에 실행 명령 표기 + 살아있으면(핑 성공) 링크 활성화.
  기본은 v21 하나만 띄우는 운용이므로 이 둘은 "개발용" 배지로 구분.
- 카드 내용 = 문서 51 1부의 8장 연대기와 결합: 각 버전이 **무엇을 처음 보여줬는지 한 줄**
  (v2 허리의 발명 / v4 LQR 대조군 / v14 MuJoCo 검증 / v19 실기 파이프라인 / v21 발표 통합 …).
  → 질의응답 Q16 "어디까지 직접 했습니까"에 **화면 하나로 답하는 무기**가 된다 (탐구일지 반전 목록과 짝).
- 발표 모드에서는 포털 진입 버튼 자체를 숨김 (심사위원 앞 기본 화면은 v21).

⚠ 확인 필요: 포함 버전 범위(전부? 대표만?), 카드 한 줄 설명 문안은 학생 검수 대상.

## 5. D — UI 잔손질 : 목록을 확정해서 한 묶음으로

제안 초기 목록 (사용자가 추가·삭제 확정해 주면 한 배치로 처리):

1. **패널 전체화면**: 3D 뷰·원위치 평면·예측점 평면 각각 Fullscreen API + `F` 키 (Esc 복귀).
2. **평면 줌/팬**: 휠 줌·드래그 팬·더블클릭 리셋. 자동 범위와 충돌하지 않게 "수동 뷰" 배지 표시.
   (마우스 집기와 충돌 주의 — 집기 모드 체크박스가 이미 있으니 팬은 집기 OFF에서만.)
3. **발표 프로파일**: 현재 H키(전부 숨김)를 3단계로 — 개발(전부) / 발표(핵심 패널만) / 무대(3D+평면만).
   어떤 컨트롤이 "발표에 불필요"한지는 **CSS 클래스 태깅**으로 — 목록 수정이 코드 수정이 안 되게.
4. **버튼 보강**: 사용자가 "부족하다"고 느낀 지점 목록 필요 — 후보: 카메라 프리셋 숫자키(문서 56 §3F),
   시뮬 속도 프리셋, 스냅샷(현 상태 PNG 저장).

## 6. E — v22: 실기 로그 ↔ 상태공간 평면

**2단계로 나눈다. 1단계(사후 재생)가 확실한 값어치이고, 2단계(실시간)는 그 위에 얹는 선택지다.**

### E1. 사후 로그 재생 (권장 착수점)

- **로그 스키마 합의가 먼저다** (펌웨어 쪽 작업과 맞물림). 제안 v1:
  `t_ms, phi, alpha, theta(또는 δ·발목각 원시), Ahat, phase(0/1/2), hold, 이벤트(트리거·FALL·GO)` —
  기존 `p2r_logger.py`(D행/E행/raw 3파일, 포트 자동탐지, 명령 겸용)를 **그대로 확장**하면 로거 신작이 필요 없다.
- v21에 「로그 불러오기」: CSV → 상태 복원 → **두 평면에 궤적·위상 색·트리거 마크** + 타임라인 스크럽
  (기존 step/back UI 문법 재사용). 참값 없음·추정값만 있음을 표시로 정직하게 (실기 링 = 추정).
- 분석 보조: 낙하 직전 구간 자동 하이라이트(|Â| 성장 구간), 같은 초기상태로 시뮬 나란히 재생(대조).
- 스파이크 정리 체크박스(문서 59)가 실기 로그에도 그대로 적용됨 — fold/REST 위상코드가 스키마에 있어야 하는 이유.

### E2. USB 실시간 스트림 (선택)

- 구조: v21 서버에 시리얼 리더 태스크 추가 (pyserial) → WS로 `ext_state` 브로드캐스트 → 평면에 라이브 점.
- 타당성 근거: 1 Mbps에서 200 Hz × ~40 byte/행 ≈ 8 KB/s — 대역은 문제없다 (57600은 불가 — 문서 55 함정 그대로).
  펌웨어는 제어 루프에서 **고정 길이 한 줄 출력**만 (블로킹 print 금지, 필요시 2~4틱당 1행 데시메이션).
- 실물 판단 요소는 코드 밖: **USB 선의 장력·비틀림이 균형에 주는 영향** — 이건 실기에서만 판정 가능.
  → E1을 기본 운용으로, E2는 벤치(지그 위) 디버깅용으로 자리매김하는 것을 권장.
