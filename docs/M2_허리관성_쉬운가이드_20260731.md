## 한 줄 요약

**로봇을 거꾸로 매달아 고정하고 → 허리 모터에 정해진 힘을 5번 걸어보고 →
파이썬 스크립트 하나 돌리면 → I_δ(허리가 돌리기 싫어하는 정도)가 숫자로 나옵니다.**

왜 재냐면: 균형 동작은 허리를 **0.06초 안에** 접어야 하는데, 이게 되는지 안 되는지가

직접 재는 수밖에 없습니다.

## 준비물

- 리포에서 받은 파일 2개:
  - `v19_bringup/firmware/motor_inertia_test/motor_inertia_test.ino`
  - `v19_bringup/calib/serial_logger.py`, `v19_bringup/calib/inertia_analysis.py`

## 1단계 — 로봇을 "거꾸로" 고정하기 (제일 중요!)

**발목이 위, 머리가 아래**가 되도록 뒤집어서, **하체를** 지그(만력기·클램프)에 물립니다.

```
   ═══ 지그(클램프) ═══
        │ 하체 (꽉 고정)
        ● 힙 관절 (여기가 움직임)
        │
        │ 상체 (아래로 축 늘어져 매달림)
        ▼
```

체크리스트 — 4개 다 확인하고 다음으로:

- [ ] 하체가 **꽉** 고정됐다 (손으로 흔들어도 지그가 안 움직임)
- [ ] **발이 바닥에도, 줄에도 안 닿는다** (완전히 공중에 떠 있음) ← 닿으면 실험 전체 무효
- [ ] 상체가 힙 관절 **아래로** 축 늘어져 있다 (이 자세가 안정 자세라 안전함)
- [ ] 힙 관절의 회전축이 **수평**이다 (상체가 앞뒤로 그네처럼 흔들리는 방향)

⚠ 상체가 좌우로 최대 45°까지 휙 움직입니다. **상체가 지나가는 자리에 손·얼굴·물건을
두지 마세요.**

---

## 2단계 — 코드 올리기

1. Arduino IDE에서 `motor_inertia_test.ino` 열기 (폴더째로 열어야 함)
2. 엔코더를 아직 배선 안 했다면: 코드 위쪽의 `USE_ENCODERS = true`를 **`false`로** 바꾸기
3. OpenCR에 업로드
4. 배터리 연결 → 시리얼 모니터 열기 (**115200 baud**)
5. `모터 OK @ 1000000` 이라고 뜨면 성공. 안 뜨면: 배터리·RS-485 케이블·모터 ID(1) 확인

---

## 3단계 — 영점 잡기

시리얼 모니터에서:

1. 상체가 **완전히 멈출 때까지** 기다린다 (조금이라도 흔들리면 안 됨)
2. `z` 입력 → `# zero set (delta=0)` 이 뜬다 ("지금 이 자세가 0도"라고 알려주는 것)
3. `p` 입력 → delta가 0 근처인지 확인

---

## 4단계 — 기록 프로그램 켜기

1. **시리얼 모니터를 닫는다** (⚠ 안 닫으면 다음 명령이 포트를 못 잡음)
2. PC 터미널(명령 프롬프트)에서:

```bash
python v19_bringup/calib/serial_logger.py COM3 itest.csv
```

(`COM3` 자리는 실제 포트 이름. 모르면 Arduino IDE의 툴 → 포트에서 봤던 것)

3. 이제 로봇이 보내는 데이터가 전부 `itest.csv` 파일로 저장됩니다.
   이 창은 실험 끝날 때까지 **켜둔 채로**, 여기에 명령을 입력합니다.

---

## 5단계 — 본 실험: 힘 걸어보기 5번

로거 창에서 아래를 **한 줄씩** 입력합니다. `i 60`은 "모터에 60만큼의 힘(전류)을 걸어라"는
뜻이고, 걸면 상체가 옆으로 휙 올라갔다가 자동으로 힘이 꺼집니다(25° 넘거나 1.2초 지나면).

**매번 반드시**: ① 상체가 휙 움직이고 힘이 꺼진다 → ② 손으로 살짝 잡아 다시 아래로
매달린 자세로 되돌린다 → ③ 완전히 멈추면 다음 명령. (많이 어긋난 것 같으면 멈춘 상태에서 `z` 한 번)

```
i 60      ← 제일 약한 힘
i 90
i 120
i 160
i 200     ← 제일 센 힘
```

각 명령 후 화면에 `E,...` 로 시작하는 줄이 뜨는데, 거기 찍히는 숫자(개략 가속도)가
**힘이 셀수록 커지면** 정상 진행 중인 겁니다.

- `i 60`인데 상체가 **꿈쩍도 안 하면**: 마찰보다 힘이 약한 것. `i 80`부터 시작하세요
- 시간 여유가 있으면 `i -60` ~ `i -200` (반대 방향)도 한 세트 — 없으면 생략 가능

끝나면: `r` (힘 끄기) → `x` (완전 정지) → 로거 창에서 Ctrl+C로 종료.

**🚨 실험 내내: 이상하면 즉시 `x`.** 로봇이 45°를 넘거나 힘이 600을 넘는 건 코드가
알아서 막아주지만, 사람이 먼저 끄는 게 항상 더 빠릅니다.

## 6단계 — 분석: 스크립트 하나 실행

```bash
python v19_bringup/calib/inertia_analysis.py itest.csv
```

이러면 끝입니다. 화면에 이런 게 나옵니다:

```
직선적합  alpha = 21.5 * tau_net + (-1.38)    R^2 = 0.999

  ★ I_delta   = 0.046 kg·m²    ← 찾던 값!
  ★ 마찰토크  = 0.064 N·m
  권장 최대 각가속도: 2594 °/s²  (Profile Acceleration ≈ 121 unit)
```

## 7단계 — 합격인지 확인하기 (3개만 보면 됨)

| 보는 것 | 합격 기준 | 불합격이면 |
|---|---|---|
| **R²** | **0.98 이상** | 측정이 흔들렸다는 뜻. 지그 고정 다시 확인하고, 매번 완전히 멈춘 뒤 명령했는지 돌아보고 재실험 |
| **I_delta** | **0.045 ~ 0.070 사이** | 0.045보다 작으면 뭔가 잘못됨(물리적으로 불가능한 값) → 자세·영점 확인 후 재실험. 0.10 넘으면 선생님/AI에게 값 공유 |
| **마찰토크** | **0.2 이하** (대략) | 크면 기어·베어링이 뻑뻑한 것. 조립 상태 점검 |

**합격이면 기록할 것 3개**: I_delta, 마찰토크, 권장 Profile Acceleration 숫자.
→ 이 값을 알려주시면 `params_v19.py`/모델 반영과 게인 재계산은 이어서 처리하면 됩니다.

## 자주 나는 문제

| 증상 | 해결 |
|---|---|
| `i`를 쳐도 안 움직임 | 힘이 마찰보다 약함 → 더 큰 숫자부터 시작 (`i 80`, `i 100`…) / 배터리 연결 확인 |
| 로거가 포트를 못 잡음 | 시리얼 모니터가 아직 열려 있음 → 닫고 다시 |
| 순식간에 45° 한계에 걸림 | 힘이 너무 셈 → 단계를 낮춰서 |
| 숫자가 들쭉날쭉 (R² 낮음) | 상체가 덜 멈춘 상태에서 다음 명령을 침 → 매번 완전히 멈추고 나서 |
| `x` 눌렀다가 다시 시작할 때 | 반드시 매달린 정지 자세에서 **`z`부터** 다시 (안 그러면 갑자기 크게 움직임) |
| 배터리가 간당간당함 | 충전하고 하세요 — 전압 낮으면 결과값이 실제보다 크게 나옵니다 |
