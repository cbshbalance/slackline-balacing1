## 0. 제어의 한 문장

**예측점이 안정모드선에서 문턱 이상 벗어나면, 벗어난 만큼(γ배) 접어 다시 선 쪽으로 보낸다.
선 위에 있으면 아무것도 하지 않는다.**

(사용자가 처음 세운 알고리즘 서술에서 조건이 뒤집혀 있었다 — 선 **위**에서 접는 것이 아니라
선 위에서는 무개입이다. 그리고 제어변수는 비율 ε 가 아니라 각도다 — 문서 41 §3-2.)

## ⚠ 이 문서를 읽는 사람에게 — 폐기된 '축약모형'에 관하여

이 문서의 8/20 초안 두 판에는 **「스칼라 A 축약모형」** 이라는 것이 나왔다.
`Ȧ = λA − k_A·δ̇` 하나짜리 1차원 장난감 시뮬로, γ 고원·회복천장·잡음한계를
그것으로 뽑아 실었었다.

**그것은 우리 연구의 일부가 아니다.** 문서 어디에도 없고, 모델 위계
(문서 31 Ⅷ: ε\* ⊂ ε\*_gen ⊂ ε\*_ft ⊂ ε_FWE ⊂ 반복 FEW)에도 속하지 않는다.
펌웨어를 짠 세션이 v21 을 못 돌리는 줄 알고 그 자리에서 급조한 검산 도구였다.

**그리고 틀렸다.** 레포의 v21 전물리로 같은 스윕을 다시 돌린 결과:

| | 축약모형이 한 말 | **v21 전물리 (정본)** |
|---|---|---|
| γ 고원 | 8.9 ~ 15.7 | **5 ~ 12** |
| 회복 천장 (γ=10) | 4.9° | **6° 이상** |
| 발목 잡음 한계 | σ 0.15~0.20° | **σ 0.10°** |

**세 개 다 틀렸고, 방향도 일정하지 않다** (고원은 좁고 높게, 천장은 낮게, 잡음은 후하게).
안정 진동모드 2차원을 통째로 뺀 모형이었으니 당연한 일이다.

**교훈:** v21 은 이미 헤드리스로 돌아간다 (`tests_v21.py` ALL PASS 확인). 시뮬 단계는

## 1. 실측값과 유도

| | 기본값 | 출처 |
|---|---|---|
| P2R | **0.417** | 문서 57 실측 |
| λ | **5.3 /s** (배가 131 ms) | 문서 53 실측 (2·3·4회 대표) |
| r | −1.6445 | ⚠ **모델 예측 — 실측 ② 미수행** |
| c₀ (절편) | 0 | ⚠ 같음 |

**유도는 코드가 한다** (하드코딩 없음):

```
w = [ −1/r , 1 , −1/(r·λ) , 1/λ ] = [0.60809, 1, 0.11473, 0.18868]
A = w·(φ, β, φ̇, β̇) + c₀/r
β = α + P2R·δ,   α = ank + phi
```

**실측값은 전부 시리얼에서 바꾼다** (§4-1). `lam 5.42` 나 `r -1.58` 한 줄이면
w 네 개와 A 오프셋이 그 자리에서 재계산되고 추정기가 리셋된다 — 재컴파일이 필요 없다.

파이프라인은 문서 46 §7 그대로 한 묶음: **200 Hz / 25 ms 기저차분 / τ≈28 ms EMA.**
⚠ 이 셋만은 일부러 런타임 대상에서 뺐다 — 따로 바꾸면 잡종이 되기 때문 (문서 45의 교훈).

## 2. 상태기계

```
IDLE ─ |Â| > trig(0.6°)  → hold += sgn · ρ·γ·Â   (ρ=0.95, γ=10, ±dlim 클립) → FOLD
```

**Â 는 `control_step` 이전 값**이고 로그에 남는 것도 그 값이다 (문서 46 §9 / 54 §7-1).

## 4. 코드에 들어간 실무 장치

### 4-1. ★ 값은 전부 이름으로 바꾼다 — 재컴파일 없이

실측이 나올 때마다 스케치를 고쳐 올리는 것은 줄 위에서 못 할 일이다.
그래서 **조정 대상을 전부 `float` 변수 + 이름표로** 만들었다.

```
lam 5.42      실측③ λ        → w 자동 재계산 + 추정기 리셋 + 배가시간 출력
r -1.58       실측② 기울기    → w 자동 재계산
c0 0.4        실측② 절편      → A 오프셋 = c0/r  (영점 자세의 A 가 그만큼 밀린다)
p2r 0.417     실측①
sgn -1        접기 방향 뒤집기 ← 부호가 틀렸을 때 재컴파일 불필요
trig 0.8      트리거 문턱
gam 11        ★줄 위 노브     → 문턱에서의 접기량·프로파일 시간을 즉시 되계산해 보여준다
```

| | |
|---|---|
| 전체 이름 (19개) | `p2r lam r c0 sgn` / `gam rho trig rel vrel dead dlim rest alim cue cuems` / `loghz vel acc` |
| 한 글자 별칭 | `f=gam c=trig e=rel o=rho l=loghz v=vel a=acc` |
| 값을 빼고 이름만 | 현재 값을 읽는다 |
| `w` | 전체 목록을 정렬해 출력 |
| `d` | **현재 값을 `.ino` 에 붙여넣을 수 있는 C 블록으로 출력** |

**세 가지 안전장치:**

1. **잠금** — 실측 상수(`p2r lam r c0 sgn`)와 `dlim` 은 **제어 정지 중에만** 바뀐다.
   달리는 중에 w 가 바뀌면 그 순간 판정이 튄다. `gam` 같은 노브는 달리면서도 된다.
2. **범위 클립 + 경고** — 값을 막지는 않고 잘라내고 말해 준다.
   `r` 이 양수면 "이론상 φ 와 β 는 반대부호" 라고 경고하되 **받아는 준다** —
   실측이 예측과 다를 수 있으므로 코드가 관측을 거부하면 안 된다.
3. **영속성은 `d` 로** — 전원을 끄면 파일의 기본값으로 돌아간다.
   확정된 값은 `d` 출력을 상수 블록에 붙여넣어 못 박는다.
   (EEPROM 저장은 넣지 않았다 — 보드별 지원이 불확실하고, 검증할 수 없는 것은 안 넣는다.)

## 5. 검증 — 두 층

| | 무엇을 확인하나 | 도구 |
|---|---|---|
| **펌웨어 논리** | 식·상태기계·파서가 의도대로인가 | Arduino API 스텁 + g++, **91개 전부 통과** |
| **제어법칙** | 그 법칙이 물리에서 서는가 | **레포 v21 전물리**, `sweep_v21.py` (3절) |

단위시험 91개의 내역:

- **이론** — 유도상수(문서 55 w 재현), A=0 이 안정모드선, 환율 φ 1°=0.608°,
  파이프라인 이득 0.817 (문서 54 예측 0.816).
- **제어** — Δδ = ρ·γ·Â 비례성 (γ 2배 → 접기량 정확히 2배), 트리거 순간 Â ≈ 문턱,
  부호 반전, T_REST 간격, ±dlim 클립, 펴기 3°/s, 놓기신호 500 ms, 안전정지.
- **파라미터 층** — `lam` 을 바꾸면 `W_PHIDOT`·`W_BETADOT` 만 바뀌고 `W_PHI` 는 안 바뀐다,
  `c0` 를 넣으면 영점 자세의 Â 가 정확히 `c0/r` 만큼 밀린다, `sgn -1` 이 접기 방향을 뒤집는다,
  범위 클립, `r` 양수 경고, 제어 중 잠금(실측은 거부·`gam` 은 허용), 모르는 이름 안내,
  `rest`·`alim` 이 실제 동작에 반영, `w`·`d` 출력, 표 19개·별칭 7개 정합.
- **입출력** — 명령파서(줄바꿈 유/무·`x` 즉시성·제어중 수동이동 거부), dry-run,
  잡음모드, CSV 13열·버림, 중앙값 필터.

> **시험 설계 함정 (기록):** β 를 직접 지정하는 구동 헬퍼(`tickBeta`)와 완만한 램프를 써야 한다.
