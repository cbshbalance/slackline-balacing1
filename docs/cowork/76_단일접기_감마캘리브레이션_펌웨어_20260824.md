> `incremental_fold_finale7.ino` 에서 **접기를 한 번만 하는** 판을 갈라냈다.
> 파일: `single_fold_gamma_cal.ino`. 목적은 문서 44 §4 의 사이클 지도

## 1. finale7 에서 바꾼 것 — 세 가지

| # | 바꾼 것 | 왜 |
|---|---|---|
| ① | **접기 1회 제한.** 문턱 돌파 → 1회 접기 → `TDONE`. 다음 시행은 `g` 를 다시 누르는 것 | 한 시행 = 한 개의 (A⁻, Δδ, A⁺) |
| ② | **자동 펴기(relax) 제거** (`rel`·`vrel` 삭제) | 펴기 자체가 킥이라 A⁺ 측정 구간을 오염시킨다 (문서 44 §4-1) |
| ③ | **고정 LOCK 창**(`lock`, 기본 120 ms) 뒤 A⁺ 확정 + 요약 자동 출력. `ftol`·`ftmax`·`rest` 삭제 | 도착 판정으로 일찍 나가면 시행마다 창 길이가 달라져 G 가 흔들린다 |

안전은 전부 유지 — `alim` 한계각, 센서 고장 자동정지, 저전압 정지, `dstep` 접기량 상한.
`TDONE` 에서도 `running` 이 유지되므로 **시행이 끝난 뒤에도 안전 감시가 계속 돈다.**
실측 상수(`p2r`·`lam`·`kv`·`r`·`c0`)는 손대지 않았다.

부수 변경: `g` 에서 **속도추정기를 리셋하지 않는다**(원본은 `primed=false`). 무장 직후의
그 한 번이 곧 측정값이라, 추정기를 비운 채 트리거가 걸리면 Â 의 속도항이 0 이 되어
A⁻ 가 통째로 틀린다. 대신 무장 유예(`armms`, §3)를 두었다.
`TDONE` 에서는 수동 δ 이동(`0`, `15` …)을 허용했다 — 시행 사이의 일상이라 막지 않았다.

## 2. ★ "정말 한 번만 접나" — 사용자 의심에서 나온 수정

사용자 지적: **"단일접기인데 왜 두 번 접는 것 같지?"**
계측해 보니 **코드는 한 번만 접는 것이 맞았고, 착시의 원인은 출력이었다.**

**확인 방법 — 가짜 서보를 붙여 `setGoalPosition` 호출을 셌다.**
`g` → 문턱 미만 300 ms → 접기 → LOCK → DONE 1000 ms(Ahat 2.5, 9.0 로 크게 유지) → `h` → `0`
→ `g` → 접기. 전 구간에서 **시행당 목표 명령은 정확히 1 회.** DONE 구간은 0 회.

**정적 확인.** `writeGoal` 은 controlStep 안 한 곳에서만 불린다. `phase = IDLE` 로 되돌리는
곳은 `g` 명령과 `k`(FALLEN 해제) 두 군데뿐 — 상태기계가 스스로 재무장하는 경로가 없다.

### 착시의 진짜 원인 두 가지

**① (고쳤다) 접기 한 번에 화면 두 줄.** dry-run 에서 `[DRY] … dcmd +8.55` 와
`>>> 접기 #1 … dd = +8.55` 가 연달아 찍혔다. ⇒ **한 줄로 합쳤다:**
`>>> 접기 #N (이 시행의 유일한 접기) …`

**② 로봇이 두 번 움직이는 것처럼 보이는 것.** 허리는 한 번 접는데 그 반작용으로 몸통·줄이
뒤따라 흔들린다. **그 뒤따르는 움직임이 바로 우리가 재려는 킥이다** — 버그가 아니라 신호다.

### 그래서 넣은 것 — 자기 증명 계수기

```
요약줄:  ★모터 명령 1 회   = ★단일접기 확인 (접기는 한 번뿐이었다)
R 줄:    goaln 열
```

1 이 아니면 화면이 경고하고 그 시행은 버린다 (dry-run 은 0 이 정상).
0 = 명령이 안 나갔다(모터 무응답·토크 OFF), 2 이상 = 중간에 끼어든 것이 있다.

> 부수 소득: 이 검증을 만들다가 테스트 하네스에서 `uint32_t` 전역을 `unsigned long`(8 byte)
> 로 extern 선언해 인접 전역(`running`·`dry_run`)을 덮어쓰는 버그를 발견했다. 하네스만의
> 문제였지만, **검증 코드가 틀리면 "정상"이 거짓으로 나온다**는 예다.

## 3. ★★ "g 를 눌렀는데 왜 바로 안 접나" — 원인 셋 (사용자 지적 2)

사용자 지적: **"트리거가 0.6° 인데 g 를 누르고 조금 있다 움직인다. 육안으로는 0.6° 를
넘은 것 같은데."** 원인이 세 개고, ★첫 번째가 거의 항상 진짜 원인이다.

### ① A 는 '기울기'가 아니다 — φ 항과 β 항이 상쇄한다

```
A = 0.664·φ + 1·β + 0.176·φ̇ + 0.265·β̇ + 0.093     (finale7 기본값)
```

φ 항과 β 항은 **부호가 반대**다. 안정모드선 `β = φ/r = −0.664·φ` 위에 있으면
**아무리 기울어도 위치항 A 는 0** 이다.

| φ | β | φ항 | β항 | off | **A** | 눈에는 |
|---:|---:|---:|---:|---:|---:|---|
| +3.0 | −2.0 | +1.99 | −2.00 | +0.09 | **+0.08** | 3° 기울어 보인다 |
| +3.0 | 0.0 | +1.99 | 0.00 | +0.09 | **+2.08** | 똑같이 3° 인데 A 는 26 배 |
| 0.0 | −2.0 | 0.00 | −2.00 | +0.09 | **−1.91** | |
| +4.0 | −2.66 | +2.66 | −2.66 | +0.09 | **+0.09** | 4° 기울어도 A≈0 |

⇒ **"육안으로 0.6° 는 넘었다" 는 A 에 대한 판단이 아니다.**
이것이 이 제어의 요점이다 — 기울어진 것 자체는 위험이 아니고, '넘어지는 쪽 모드' 에
실린 성분만 위험이다. (그래서 노브가 하나로 줄어드는 것이고, 문서 09 §1.1 의 A 정의 그대로다)

**조치: `p` 가 A 를 항별로 분해해 찍는다.**

```
---- A 분해 (지금 A 가 무엇으로 이루어졌나) ----
   phi   +3.00 deg   x 0.6640  = +1.992
   beta  -2.00 deg   x 1.0000  = -2.000
   dphi  +1.2 dps    x 0.1760  = +0.211
   dbeta -0.5 dps    x 0.2650  = -0.133
   offset(c0/r)                = +0.093
   ----------------------------------------
   위치항 합 +0.085   속도항 합 +0.079   ->  A = +0.164   (문턱 0.60)
   ★안정모드선: phi=+3.00 일 때 beta 가 -1.99 이면 위치항 A=0.
     실제 beta -2.00 -> 선에서 -0.01 deg 벗어남
```

속도항이 위치항보다 크면 "지금은 자세보다 움직이는 방향이 A 를 만들고 있다" 도 알려 준다
(문서 70 §7-3: 불안정 모드 위에서 속도 비중은 κ/(1+κ) ≈ 65 %).

### ② 무장 유예 `armms` — 일부러 넣은 200 ms

`g` 직후 이만큼은 트리거를 안 건다. **왜 필요한가:** `g` 명령 자체가 루프를 세운다
(`motorRetry()` 는 `delay(100)`×3, `torqueRestoreHere()`·`readDelta()` 도 통신 대기).
그동안 `readState` 가 안 도니 `phi_hist` 에 멈추기 전 값이 남고, 루프가 재개되면 그
**5 샘플 창(25 ms 로 나눈다)이 수백 ms 어치 변화를 25 ms 로 나눠** 속도가 10 배 넘게 부푼다.
그 한 샘플로 접으면 그 시행은 통째로 쓰레기다. EMA(a=0.15)로 스파이크가 사라지는 데
40 샘플 = 200 ms — 그것이 기본값의 근거.

**⚠ 대가:** 유예 동안 A 는 `e^{λt}` 로 자란다.

| armms | A 배율 | A 0.6 → |
|---:|---:|---:|
| 0 | 1.00 | 0.60 |
| 100 | 1.76 | 1.06 |
| **200** | **3.10** | **1.86** |
| 300 | 5.46 | 3.28 |

⇒ **`g` 를 '놓기 전에' 누르면 대가가 없다** — 유예가 손에 들고 있는 동안 지나간다.
이미 놓은 뒤에 누르는 방식이면 `armms 100` 또는 `0` 으로 줄일 것 (`t` 로 overrun 0 확인 후).

**조치: 유예가 트리거를 막고 있으면 조용히 넘어가지 않는다.**

```
(유예) 문턱을 넘었지만 아직 안 접는다 — 남은 195 ms   Ahat=1.20
       [armms 200 — 놓기 전에 g 를 누르거나 armms 를 줄일 것]
```

`armms` 를 런타임 파라미터로 뺐다 (0~2000, 기본 200).

### ③ `!primed` 게이트

`z` 나 유도 파라미터 변경 직후 한 샘플(5 ms)뿐이라 사실상 원인이 아니지만,
문턱을 넘었는데 안 접으면 "(대기) 속도추정기가 아직 안 찼다" 를 찍게 했다.

## 4. ★ 이 실험이 sgn 을 결정한다 — γ 보다 이게 먼저다

문서 72·finale7 헤더의 미결: 논증 A(매달기 → +1)와 논증 B(판정식 미분 → −1)가 서로 반대.
**요약줄의 `g_est` 부호가 그 답이다.**

```
g_est > 0  →  접기가 A 를 줄였다  →  지금 sgn 이 맞다
g_est < 0  →  접기가 A 를 키웠다  →  ★sgn 을 뒤집고 다시 잴 것
```

간접 증상("여러 번 접다 보니 ±55° 에 붙더라", γ 부족과 구분이 안 됨)이 아니라
**한 시행짜리 직접 측정**이다. ⇒ **낮은 γ(5) 로 첫 두세 시행을 먼저 돌릴 것.**
sgn 이 반대인 채로 24 시행을 모으면 데이터 전체의 g 부호가 뒤집힌 채 나온다.

## 5. 작업 중 눈에 띈 상수 불일치 두 건 (값은 손대지 않고 주석으로만 남겼다)

**① `lam` 이 5.44 냐 5.66 이냐** — finale7 코드는 `LAMBDA = 5.66f` 인데 헤더 배너·기동
문구·sanityWarn 은 5.44 라고 쓴다. 배가시간 122 vs 127 ms, **G_pred 1.972 vs 1.921 로 4 % 차.**
문서 70 은 §4(동정) 5.66±0.09, §5(φ 배가시간, 모델 없이) 5.44±0.59 로 둘 다 정본이고,
문서 73 은 "w·κ 와 한 묶음이니 5.66" 을 택했다.
⇒ **이 캘리브레이션이 가려 준다** — 적합 G 를 두 값에 대 보는 것이 게이트 H1 이다.

**② `c0` 이 −0.14 냐 −1.11 이냐** — finale7 은 `LINE_C = -0.14f (±0.13)` 을 쓰고 "−1.11 은
폐기된 회귀절편" 이라고 적었는데, **프로젝트의 문서 70 §4-1·§8 에는 아직 −1.11 ± 0.86
「미확정」 으로 남아 있다**(보완측정 미완 ①). A 오프셋 차이는
`(−0.14 − (−1.11))/(−1.506) = −0.64°` — **트리거 문턱 0.6° 와 같은 자릿수다.**
⇒ 회귀에 **절편을 넣은 판**을 한 번 돌리면 이 절편도 다시 재진다.

## 6. 한 시행의 절차

```
z → n(잡음) → y+g(부호확인) → h,y → m → gam 5 → z → g(무장) → READY 뜨면 놓기
→ 자동 접기 1회 → LOCK 120 ms → 요약 R 줄 → h → 0 (δ 원위치) → gam 바꾸고 → g
```

★`g` 는 **놓기 전에** 누른다 (§3 ②). 안 접고 있으면 `p` 로 A 분해를 볼 것 (§3 ①).

## 7. 요약 줄

```
R,trial,t_ms,A_minus,dd_cmd,dd_act,d0,A_plus,lock_ms,prof_ms,G_pred,g_est,gam_est,gam_set,goaln,clip,err
```

- **`dd_act` 로 회귀할 것.** `dd_cmd` 는 명령값이고 서보가 1~3.4° 못 미친다
  (문서 64 §4-3 / 문서 70 §3 의 명령 40° → 실제 36.64°).
- **`goaln != 1` 인 줄은 버린다** (§2). `err != 0` 도 버린다. `clip = 1` 은 dstep 에 잘린 시행.
- `g_est`·`gam_est` 는 G 를 `e^{lam·T}` 로 **고정한** 거친 값. 현장 눈금·부호 판정용.
- 프로파일 시간이 창의 80 % 를 넘으면 화면이 경고한다 (γ 20 + dstep 클립에서 실제로 걸린다).

**정본 회귀:** `A_plus = G·A_minus − g·dd_act` 를 절편 없는 2변수 최소제곱 → `γ_h = G/g`.

## 8. ⚠ 이 모드의 한계 — 공선성

Δδ = ρ·γ·Â 이므로 **Δδ 가 A⁻ 에 비례**한다 (문서 44 §4-2). 깨는 방법:

- **(a) γ 를 시행마다 바꾼다** — `gam 5 / 9 / 14 / 20` 을 **섞어서** 각 6 시행 = 24 시행. ★권장안.
- **(b) 유지각 δ₀ 를 바꾼다** — `h → 15 → g`. g(δ₀) 가 평평한지가 문서 44 §4-4 의 질문.

정석인 탐침 모드(Δδ 를 A 와 완전 독립 주입)는 발동 규약이 달라지므로 넣지 않았다.

## 9. LOCK 창을 왜 120 ms 로 두었나

λ = 5.66 → T₂ = 122 ms. `lock` 120 ms ≈ 0.98·T₂.

- **짧으면** 접기 프로파일이 안 끝난 채 A⁺ 를 읽는다 → g 가 작게 나온다.
  γ 9 → 5.13° 는 51 ms, γ 20 → 11.4° 는 76 ms, dstep 20° 는 101 ms. ⇒ 90 ms 아래로 내리지 말 것.
- **길면** A 가 자라 소각 근사(|φ| < 5°, 문서 70 §4-4)를 벗어난다.
  lock 200 ms 면 G_pred = 3.1 — A⁻ 0.6° 가 1.9° (회복 천장 2.8~4.0°).

**★한 스윕 안에서는 절대 바꾸지 말 것.** 창이 다르면 G 가 달라져 같은 회귀에 못 넣는다.
