# 77. finale7 알고리즘의 호스트 이식 — fold_host.py + fold_bridge.ino (2026-08-24)

`incremental_fold_finale7.ino` 의 판정부를 파이썬으로 옮기고, 그 위에 `p2r_logger.py` 형식의
시리얼모니터 + CSV 로거를 합쳤다. 둘로 나뉜다.

| 파일 | 하는 일 |
|---|---|
| `fold_bridge.ino` | ★제어 없음. 엔코더 원값 2개 + δ 를 200 Hz 로 올려보내고(`R` 행), 내려온 δ 목표를 서보에 쓴다. 토크·복구·전류제한·부하시험만 대신한다. |

`t_ms,phi,ank,alpha,beta,dphi,dbeta,Ahat,hold,del_now,phase,cue,err`.

```
python fold_host.py --selftest        # ★장비 없이 이식이 맞는지 40여 항목 점검 (전부 통과)
python fold_host.py sim1 --fake       # 장비 없이 가상로봇으로 전 과정
```

## 1. 옮기면서 달라진 것 — 다섯 개뿐

1. **한 틱의 정의**: 보드의 5 ms 타이머가 아니라 **R 행이 도착할 때마다** 한 틱. 호스트 타이머로 돌면
   도착 안 한 샘플로 판정하거나 같은 샘플을 두 번 쓴다.
2. **지연이 한 왕복 늘어난다**: `t` 에 「왕복 지연」을 찍는다. 10 ms 를 넘으면 kv 를 만지기 전에 그것부터.
3. **속도 파이프라인은 '상수'가 아니라 '시간'을 지켰다**: 200 Hz 면 `VEL_N=5, EMA_A=0.15` 가 글자
   그대로 나온다(완전 동일). 주기를 낮추면 25 ms 기저차분·τ 28 ms 를 지키도록 N 과 a 를 다시 만든다.
   상수를 고정하면 필터 시간상수가 통째로 바뀐다(문서 45의 '잡종'). `--pipe fixed` 로 강제 가능하나 권하지 않음.
4. **호스트가 죽을 위험**: 보드 워치독 `wd`(기본 300 ms). G 가 안 오면 목표를 **지금 자리로 얼린다**.
   토크는 끊지 않는다 — 줄 위에서 토크를 끊으면 허리가 무게에 접혀 더 빨리 넘어진다.
5. **잡음(n)은 호스트에서, 전압·전류는 보드가 10 Hz 로 `P` 행에 실어 보내고 vmin 판정은 호스트에서.**

## 2. 원본에서 주석과 코드가 어긋난 곳 두 군데 (몰래 고치지 않고 코드 값을 따랐다)

| | 헤더 주석 | 실제 코드 | 차이 |
|---|---|---|---|
| `LAMBDA` | lam 5.44 (배가 127 ms) | `5.66f` (배가 122 ms) | 4 % |
| `CUE_TH` | cue 0.3 | `1.0f` | 놓기신호 문턱이 3배 |

`cue` 는 놓기신호 **꺼짐** 문턱까지 바꾼다: `cue_off = max(trig, cue×1.5)`.
1.0 이면 꺼짐 문턱이 1.5°, 0.3 이면 trig(0.6°) 다. 어느 쪽이 의도인지 정해야 한다.

## 3. ★재현하면서 나온 것 — 접기 자체가 Â 를 문턱의 18배까지 올린다

포팅한 코드에 **φ·α 를 완전히 고정한 채 δ 만 문턱 접기량(5.13°) 만큼 움직여** 먹여 봤다.
즉 아래 숫자는 물리가 아니라 **판정식 + 파이프라인의 산술**이다.

| 시각 (접기 시작 기준) | dbeta [deg/s] | Ahat | 상태 |
|---|---|---|---|
| 0 ms | 0.0 | 0.09 | FOLD 시작 |
| 40 ms | 31.7 | **10.50** | FOLD |
| 60 ms | 33.0 | **11.05** | REST 진입 |
| 120 ms | 5.0 | **3.61** | ★IDLE 복귀 = 다시 판정 시작 |
| 280 ms | 0.03 | **2.30** | 정착 |

두 가지가 겹쳐 있다.

- **β̇ 스파이크 (일시적)**: β = α + P2R·δ 이므로 β̇ 에 서보 자기 운동이 그대로 들어간다.
  피크 속도 203 deg/s → w_β̇·P2R·δ̇ 로 Â 가 11까지 오른다(문턱의 18배).
  REST 60 ms 는 τ=28 ms 의 2.1배지만, IDLE 복귀 시점에도 **3.6° = 문턱의 6배**가 남는다.
  → 접은 직후 반대 방향으로 헛트리거가 걸린다. 문서 45 「헛트리거·늦은트리거·스윙」과
  문서 59 「스파이크 정정」이 가리키던 것이 이것일 가능성이 크다.
- **β 위치항 (영구적)**: Δβ = P2R·Δδ = 0.4285×5.13 = **+2.20°**. 즉 접기 한 번이 Â 를
  같은 부호로 2.2° (문턱의 3.7배) 밀어 올린다. 이것이 헤더 [논증 B] 그 자체다.

**확인 방법 — 새 실험이 필요 없다.** 기존 D행 로그에서 `phase` 가 0→1 로 바뀌는 순간을 찾아
그 전후의 `dbeta` 와 `Ahat` 을 보면 위 표가 실기에서도 나오는지 바로 보인다.

## 4. ★sgn 을 계산이 아니라 로그로 가르는 길 — 실측④ 제안

접기 한 번이 A 를 얼마나 옮기는지, 즉 **dA/dδ** 하나만 알면 sgn 도 γ 도 동시에 정해진다.

- 발목이 δ 를 따라가지 않으면(논증 B): dA/dδ = **+P2R = +0.4285** → sgn = **−1**, deadbeat γ ≈ 2.5
- 발목이 δ 를 완전히 따라가면(매달기 조건, β 보존): dA/dδ = **0** → 접기가 A 를 못 움직인다
- 그보다 더 따라가면: dA/dδ **< 0** → sgn = **+1**

일반형은 α 가 δ 를 따라가는 몫을 q 라 할 때 **dA/dδ = P2R − q** 이고,
매달기 시험은 q = P2R 인 특수 조건(무게중심이 축 아래)에서 잰 것이라 이 값을 말해 주지 못한다.
헤더가 "매달기는 δ→α 는 말해 주지만 δ→β 는 말해 주지 않는다" 고 쓴 것과 같은 이야기다.

한편 실기 관찰 γ ≈ 9 를 deadbeat 로 보면 |dA/dδ| ≈ e^{λ·t_fold}/(ρ·γ) ≈ 1.6/8.55 ≈ **0.19**,
즉 P2R 의 절반 아래다. **γ 라는 노브 하나가 이미 dA/dδ 를 재고 있었던 셈이다.**

**뽑는 법**: D행 로그에서 접기(phase 0→1)마다
`Δδ = del_now(접기 완료 후) − del_now(접기 직전)` 과
`ΔAhat = Ahat(접기 후 200 ms, 스파이크가 죽은 뒤) − Ahat(접기 직전)` 을 모아 회귀.
기울기의 **부호**가 sgn 을 정하고, **크기**가 γ 의 상한을 정한다.
필요하면 이 회귀 스크립트도 만들어 두겠다.

⚠ 위 3·4 는 어디까지나 판정식과 로그에서 나온 것이다. 줄 위에 올리기 전 **y(dry-run) 바닥 시험**은
그대로 해야 한다.

## 5. `--fake` 가상로봇에 대하여

장비 없이 배관(파싱→판정→상태기계→CSV→안전정지)을 전부 밟아 보려고 붙인 **장난감**이다.
1차 발산(Ȧ = λA)과 프로파일 서보, 실측 잡음(φ 0.010° / 발목 0.035°)만 있다.
`--fake-dadd` 로 위 dA/dδ 를 넣는다(기본 0.19). **이걸로 sgn 이나 γ 를 고르면 안 된다.**
기본값으로 돌리면 몇 초 버티다 넘어지는데, 그 이유가 위 3절의 β̇ 스파이크다 —
즉 이 장난감의 실패 자체가 3절을 눈으로 보여 준다.

## 6. ★2026-08-24 정정 — "명령이 하나도 안 먹는다" 의 원인

접속 직후 브리지 초기화 명령 `S 200.0` / `W 300` / `V 250 373` 을 보내고 있었다.
finale7 펌웨어는 그 첫 글자만 보고 `s`(출력 정지) · `w`(목록) · `v`(속도) 로 읽는다.
⇒ 브리지를 안 올린 보드에 접속하면 **그 순간 보드 화면이 꺼진다.** 그 뒤로는 무엇을 쳐도
반응이 없어 보인다. 실행 방법이 따로 있었던 게 아니라 이쪽 버그였다.

1. **말을 걸기 전에 듣는다.** 최대 8 초 동안 한 글자도 안 보내고 올라오는 줄만 본다.
   `R,`/`P,` → 브리지, `D,`/`=== incremental_fold` 배너 → finale7.
