# 발표 영상 시나리오 — 씬 표 v1 (러프컷 설계도) — 2026-08-15

> 전람회 발표 전체가 이 영상 하나를 기반으로 하도록 설계한다.
> **결론: 전용 도구는 없다. three.js 단일 씬 + "감독(director) 레이어"로 코드로 만든다.**
> 같은 코드에서 ① 키보드로 씬을 넘기는 **발표 앱** ② 헤드리스 렌더로 굽는 **mp4** 둘 다 나온다.
>
> 이 문서는 러프컷의 설계도다. 여기 숫자를 고치면 영상이 고쳐지도록 `scenario.json` 스키마를 함께 정의한다.

---

## 0. 왜 코드인가 — 씬 전환이 전부 기존 파라미터의 보간이다

| 시나리오 장면 | 이미 있는 자산 | 새로 할 일 |
|---|---|---|
| ① 실사 정지 → v19 오버랩 | `v19_sim/static` three.js 씬 | 정지프레임 배경판 + 기하 눈맞춤 + 알파 페이드 |
| ② 기둥/줄 축소 | `renderer3d`가 매 프레임 `p.L_pole`, `p.R` 읽어 rebuild | 시간의 함수로 lerp |
| ③ xz 평면 → 전체화면 | `setSideView()` / `set3DView()` 존재 | **둘 사이를 보간** + 평면 mesh fade-in |
| ④ v2 모델 · φ,α,θ → φ,β,δ | 같은 관절점 = 같은 기하 | 각호(arc) + 라벨 crossfade |
| ⑤ 접기·대기·펴기 | v19_sim MuJoCo 실제 궤적 | 색 규약 트레일(빨강·파랑·금색) |
| ⑥ 상태공간 + 예측점 평면 | `v20_pred_plane` 캔버스 통째 | **CanvasTexture**로 3D 평면에 붙여 카메라 진입 |
| ⑦ ε\* · 증분 접기 | v20_pred_plane 계산 그대로 | 마우스 대신 스크립트가 조작 |
| ⑧ 실기 주행 | 실사 영상 | 붙이기 |

**설계 원칙 2개**

1. **물리는 미리 굽는다(bake).** v19_sim(MuJoCo)에서 궤적을 `traj_*.json`으로 뽑고 브라우저는 재생만 한다. 렌더가 결정론적이 되고 발표 직전에 다시 뽑아도 그림이 흔들리지 않는다.
2. **실시간 재생이 아니라 프레임 구동.** `window.__seek(t)` 하나만 노출 → Playwright 헤드리스 크로미움이 `t = n/60`마다 스크린샷 → ffmpeg. 노트북 성능과 무관, 4K 가능, 몇 번이든 재현.

## 2. 씬별 상세

### S1 — 실사 정지 → v19 오버랩 (0:00–0:20)

| | |
|---|---|
| 배경 | 줄타기 실사 영상 → `t=6.0 s`에서 정지(프리즈 프레임) |
| 카메라 | 고정. 실사 프레임의 FOV·위치에 three.js 카메라를 손으로 매칭 |
| 애니메이션 | 0–6 s 실사 재생 → 6–8 s 정지 + 채도 −60% → 8–14 s v19 모델 알파 0→1 → 14–20 s 실사 알파 1→0.25 |
| 맞출 것 | 기둥 2개의 화면상 위치, 줄 높이, 광대 신장 ≈ 모델 (L₁+L₂) |
| 라벨 | 없음 (첫 20초는 그림만) |

**카메라 매칭은 PnP 같은 정밀 기법을 쓰지 말 것.** 기둥 2개 + 줄 높이면 `L_pole`, `R`, `camera.position`, `fov` 4개 슬라이더로 눈맞춤이 충분하고 훨씬 빠르다. 매칭 결과는 `scenario.json`에 숫자로 박아 재현한다.

⚠ **실사 영상 라이선스 확인 필요** — 전람회 제출물이므로 출처·이용허락을 문서에 남길 것.

### S2 — 필요한 것만 남기기 (0:20–0:42) ★재설계 제안

사용자 원안은 "기둥 간격이 600 mm로 줄어든다"였다. 시각적으로는 강력하지만 **물리적으로 한 단계가 생략되어 있어** 심사위원 질문에 취약하다.

- 사람 줄타기에서 **R = 0.70 m는 처진 줄의 곡률반경**이지 기둥 간격이 아니다 (기둥 간격은 수 m).
- 로봇 '어름이'는 그 곡률을 **V자(사다리꼴) 두 줄**로 기구적으로 재현하고, 그때 매다는 점 간격 **D ≈ 600 mm**가 **R = 0.433 m**를 만든다: `R = √((L/2)² − (D/2)²)`, L ≈ 1.05 m.

그래서 **두 박자로 쪼갠다** — 이러면 "그네처럼 생겼지만 사실 줄타기에서 필요한 부분만 모델링한 것"이 정확하게 전달된다.

| 박자 | 구간 | 내용 |
|---|---|---|
| **S2a 추출** | 20–30 s | 실사 줄의 처짐 위로 곡률원과 반지름 화살표 `R = 0.70 m`가 그려짐 → 기둥이 페이드 아웃. 자막: **"필요한 것은 기둥 간격이 아니라 R 하나였다"** |
| **S2b 축소** | 30–38 s | `R: 0.70 → 0.433 m` lerp. 동시에 모델 스케일이 사람 → 로봇으로 |
| **S2c 기구화** | 38–42 s | 카메라가 **축 방향 뷰**로 돌아 V자 두 줄이 나타나고 `D = 600 mm` 치수선 + `R = √((L/2)²−(D/2)²)` 표시 |

⚠ **축소 구간에서는 물리를 멈추고 기하만 보간한다.** R이 바뀌면 λ_u가 3.538 → 5.813 /s로 바뀌므로 궤적을 이어서 재생하면 거짓말이 된다. S2 끝에서 파라미터 세트를 「사람 스케일 → 로봇·실측정본」으로 **갈아끼운다**(문서 42의 3세트 구조를 그대로 사용).

| 세트 | R | λ_u | ω_eff |
|---|---|---|---|
| 사람 스케일 | 0.70 m | 3.538 /s | 6.302 |
| 로봇 · 실측정본 | 0.433 m | 5.813 /s | 7.105 |

### S4 — v2 모델 · φ,α,θ → φ,β,δ (0:54–1:29)

영상 전체에서 **가장 설명 밀도가 높은 씬**. 라벨과 각호(arc)만으로 구성된다.

| 구간 | 내용 |
|---|---|
| 54–62 s | 2링크 막대가 선으로 그려짐. 발목·힙·머리 마커. 연직 기준선(점선) |
| 62–74 s | **1세트**: `φ` (줄 흔들림, 곡률중심 기준 호) → `α` (하체 절대각) → `θ` (상체 절대각). 각호가 하나씩 등장, 각각 2 s 강조 후 반투명 유지 |
| 74–80 s | 무게중심 마커 등장 + `x_CoM = −Rφ + (p₁α + p₂θ)/M_t` 수식 |
| 80–89 s | **2세트로 갈아타기**: `α`,`θ` 호가 crossfade 하며 `β` (CoM 기울기)와 `δ = θ − α` (접힘)로 바뀜. 변환식 표시:<br>`α = c_β β − (p₂/p_s) δ`, `θ = c_β β + (p₁/p_s) δ`, `c_β = M_t h / p_s` |
| 자막 | "좌표를 갈아타자 시스템이 두 조각으로 갈라졌다 — 넘어짐(β)과 접힘(δ)" |

**갈아타기가 이 씬의 핵심이므로 같은 관절점에서 호만 바뀌게 만든다.** 막대가 움직이면 "다른 모델"로 오해된다. δ만 실제로 움직여(0 → 15° → 0) 접힘 각의 의미를 보이고, 그 동안 β가 변하지 않는 것을 함께 보이면 `M_p[φ,δ] = 0`, `G_p[(φ,β),δ] = 0` 구조 검산이 그림으로 설명된다.

색 규약: `φ` 파랑 / `α` 청록 / `θ` 보라 / `β` 진홍 / `δ` 주황.

### S5 — 3D 복귀 · 접기·대기·펴기 (1:29–1:59)

| 구간 | 내용 |
|---|---|
| 89–95 s | 카메라 side → 3D 복귀 (S3의 역보간, 단 `R = 0.433` 로봇 기하) |
| 95–125 s | v19_sim에서 구운 FWE 1사이클 궤적 재생. 발 자취 트레일에 **접기 빨강 / 대기 파랑 / 펴기 금색** |
| 오버레이 | 좌상단에 `A`(위험도) 막대, 우하단에 `δ` 값. 구간명 자막(접기 / 대기 / 펴기)이 상태에 따라 자동 전환 |
| 자막 | "허리 접기가 발을 무게중심 너머로 던져 중력 토크를 반전시킨다" |

⚠ **서사 주의(문서 10 §4).** 최종 제어기는 완전사이클 FWE가 아니라 **증분 접기 + 느린 복귀(펴기 생략)**다. 제목에서도 "접고-기다리고-펴기"를 뺐다. 그러나 **발표 내부에서는 발전 서사로 쓰는 것이 공식 방침**이므로, 사용자 원안의 순서(S5 완전사이클 → S7 증분 접기)가 정확히 그 구조다. S7에서 "펴지 않아도 유계"가 승격되는 전환을 명시적으로 보여줄 것.

### S6 — (β,φ) 상태공간 + 안정선 + 예측점 평면 (1:59–2:29)

| 구간 | 내용 |
|---|---|
| 119–127 s | 로봇 옆 공중에 흰 사각 평면이 세워짐. `v20_pred_plane` 캔버스를 **CanvasTexture**로 부착. 축 `β`(가로) / `φ`(세로) |
| 127–134 s | **초록 안정모드선**이 그려짐. 원위치 점(검정)이 실시간으로 찍힘 — 선 위에 있는데도 발산하는 것을 보여줌 |
| 134–142 s | 자막 "그림자에는 속도가 숨는다". 원위치 점 → **예측점**으로 이동하는 화살표: `q_pred = q + (λ_u I − D)⁻¹ q̇` |
| 142–149 s | 카메라가 평면 정면으로 날아들어 전체화면. 3D 씬은 우하단 PIP로 축소 |

구현 메모: 평면 정면 진입 후에는 CanvasTexture를 버리고 **DOM 캔버스를 전체화면으로 크로스페이드**하는 편이 선명하다(텍스처 해상도 한계 회피).

## 3. `scenario.json` 스키마

발표 리허설하면서 **이 파일의 숫자만 고치면** 영상이 고쳐지도록 한다.

```jsonc
{
  "fps": 60,
  "resolution": [3840, 2160],
  "paramSets": {                       // 문서 42의 3세트
    "human":      { "R": 0.70,  "lambda_u": 3.538, "omega_eff": 6.302 },
    "robot_meas": { "R": 0.433, "lambda_u": 5.813, "omega_eff": 7.105 }
  },
  "trajectories": {                    // v19_sim에서 미리 구운 것
    "fwe_cycle":  "traj/fwe_cycle.json",
    "incremental":"traj/incremental.json"
  },
  "scenes": [
    {
      "id": "S1",
      "t0": 0.0, "dur": 20.0,
      "hold": true,                    // 발표 앱에서 정지점
      "paramSet": "human",
      "physics": "frozen",             // frozen | play:<trajId>
      "camera": { "mode": "matched", "pos": [4.2, -6.1, 2.3], "target": [0,0,1.9], "fov": 38 },
      "layers": [
        { "kind": "video",  "src": "media/tightrope.mp4",
          "keys": [ {"t":0,"time":0,"alpha":1}, {"t":6,"time":6,"alpha":1},
                    {"t":8,"time":6,"alpha":1,"saturation":0.4},
                    {"t":20,"time":6,"alpha":0.25} ] },
        { "kind": "model3d",
          "keys": [ {"t":8,"alpha":0}, {"t":14,"alpha":1} ] }
      ],
      "labels": []
    },
    {
      "id": "S2b",
      "t0": 30.0, "dur": 8.0,
      "physics": "frozen",
      "tween": [ { "target": "params.R", "from": 0.70, "to": 0.433, "ease": "inOutCubic" } ],
      "onEnd": { "setParamSet": "robot_meas" },
      "labels": [ { "text": "R = {R:.3f} m", "anchor": "ropeCenter", "t0": 0, "dur": 8 } ]
    }
    // ... S3 ~ S8
  ]
}
```

**핵심 계약: `window.__seek(t)`** — 어떤 `t`를 넣어도 그 시각의 화면을 결정론적으로 만든다. 누적 상태(requestAnimationFrame 델타, OrbitControls damping)를 쓰면 안 된다. 이 계약 하나가 지켜지면 발표 앱(키보드로 `t` 점프)과 오프라인 렌더(`t = n/60` 순회)가 같은 코드에서 나온다.

## 4. 폴더 구조 제안

기존 폴더는 **읽기만** 하고 건드리지 않는다(문서 42의 선례).

```
presentation/
  index.html            # 감독 레이어 + 씬 호스트
  scenario.json         # 위 스키마 — 리허설하며 여기 숫자만 고침
  src/
    director.js         # seek(t) → 씬 상태 결정 (누적 상태 없음)
    tween.js            # 키프레임 보간 · easing
    scenes/S1..S8.js    # 씬별 세팅 함수
    overlay.js          # 각호 · 라벨 · 수식 (SVG/DOM)
    adapters/
      v19_scene.js      # v19_sim/static 의 three.js 씬을 가져다 씀
      pred_plane.js     # v20_pred_plane 캔버스를 CanvasTexture/DOM 으로
  traj/                 # v19_sim 에서 구운 궤적 JSON
  media/                # 실사 영상 (라이선스 기록 필수)
  bake_traj.py          # MuJoCo → traj/*.json
  render.mjs            # Playwright 프레임 캡처 → ffmpeg → mp4
```
