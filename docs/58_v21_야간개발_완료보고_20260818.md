## 2. ★ 물리 발견 — "선 위 놓기"의 정직한 한계 (교육 시나리오 정정)

수용시험 중 발견. **완벽히 안정모드선 위에 놓아도 전물리에서는 넘어진다** — 비선형 씨딩(진폭² 비례, β=1°에서 유효 씨드 ~0.008°)이 λ≈5.9 /s 로 증폭되어:

| 놓기 | 버팀 | 왕복 |
|---|---|---|
| 선 위 (β 0.5~2°) | **1.5~2.0 s** | 2~3회 흔들린 뒤 낙하 |
| 선 밖 (\|A\| 1.2~1.8°) | **0.80~0.86 s** | 0~1회, 즉시 한쪽으로 |
| **제어 ON (트리거 0.6°)** | **10점 전부 8 s+ 생존** | 접기 21~28회 |

수치 씨딩만으로도 상한 ~3 s — 도구가 아니라 **물리의 성질**이다 (배가 117 ms 가 그만큼 가혹).
실물도 같은 물리이므로:
- 문서 55 의 교육 시나리오 "선 위 클릭 → 잦아든다"는 **"선 위 = 왕복하며 오래 버틴다 / 선 밖 = 곧장 한쪽으로 / 제어 ON = 다 잡는다"** 3단 대조로 정정하는 것이 정직하고, 발표 임팩트도 오히려 크다.
- 문서 46 이 실측② 합격을 "3회 이상 진동"으로 정한 것과 정확히 정합 — **실측② 때 놓기당 관측창은 ~2 s 로 잡을 것.**
- 시험 기준(문서 56 §4 1A)은 이 대조 기준으로 갱신했다: 대조비 min(선위)/max(선밖) ≥ 1.5 (실측 1.73).

## 3. 구현 설계 요점 (다음 세션용)

- `cmd:"pose"` = qpos 만 세팅·브로드캐스트 (clear 없음 — 그래프·궤적 보존). hover 진입/이탈은 `pose_begin`(snapshot)/`pose_end`(restore) — 엔진 기존 스냅샷 재사용.
- `x0` 확장: `phid0/alphad0/thetad0` [deg/s]. qvel 부호 = qpos 규약의 시간미분 (qvel[phi]=−φ̇, qvel[ankle]=α̇+φ̇, qvel[hip]=θ̇−α̇). 속도 키가 없으면 0 리셋 (슬라이더·평면클릭 하위호환).
- 평면 역변환: drawPlane 이 프레임마다 {m,cx,cy,R} 저장 → 마우스 CSS px × devicePixelRatio.
- 현재점을 hist 가 아니라 **lastView 기준**으로 그리도록 변경 — pose 미리보기·리셋 직후에도 점이 따라온다 (빈 hist 에서도 평면·선·띠 렌더).
- 키네마틱 시연: Δβ=−kFold·δ, Δφ=+kFold·sCoM·δ (PL 상수) → 등고선과 자기일관. 3D 는 α=β−P2R·δ, θ=α+δ.
- 오버랩: 사진 레이어(letterbox = 사진 종횡비) + 렌더러 alpha + 사람스케일 씬(jG)은 시각 전용 — 물리 리빌드 없음. 모프 = 기하·카메라 동시 트윈, 종료 시 v19 표준 화면 자동 복귀.
- 정합 씬 상수는 `SCENE_JULTAGI` (index.html) + `scenes/jultagi_20260817.json` 이중 보관.

### 개발 중 밟은 함정 (재발 방지)
- **`const` 선언을 `frame();` 첫 호출 뒤에 두면 TDZ 로 스크립트 전체가 죽는다** — 상태 선언은 전부 스크립트 상단 상태 구역에. (이 실수로 WS 연결까지 침묵 실패했다)
- pkill 로 서버 죽일 때 패턴이 자기 셸 명령줄과 매치되지 않게 (포트 기준 fuser 권장).

## 4. 남은 일 (우선순위 제안)

1. **4단계**: 실측선 오버레이 (r·절편·λ 입력 → 별색 선·띠·실측 w 병기) — drawPlane 에 두 번째 선 세트만 추가하면 됨. 발목잡음 프리셋은 `_measure` 채널별 σ 확장 필요.
2. **씬 체인 데이터화** (문서 56 §3F): SCENES 배열 + [ ] 키 — 대본 확정 전이므로 순서 교체 쉬운 구조로.
3. 로봇 실기 영상 오버랩 — 같은 레이어에 소재만.
4. 베어링 교체 후: 잡음 재측정 (문서 54 방법) → 잡음 프리셋 값 갱신.
5. 실측 ② 수행 시 → 실측선 오버레이에 기입 → "시뮬 예측 vs 실물" 한 화면.

## 5. 알려진 한계 (설계 의도 포함)

- hover 미리보기는 **정지 중에만** (러닝 중 클릭은 즉시 재시작으로 동작). 추정 링은 hover 중 갱신 안 됨 (추정기는 실제로 그 상태를 본 적 없음 — 정직한 표시).
- 예측점 평면에는 마우스 집기 없음 (속도 0 이면 원위치와 동일 — 4D 입력칸이 그 역할).
- 정합 카메라 fov 30° 는 사진(줌 영상) 전용 — 일반 화면은 42°. 뷰 버튼이 자동 복원.
- E2E 의 CoM 기울기 검증은 기본 파라미터(설계추정치, sCoM 0.7937)에서 수행 — 빨간 버튼 후에는 실측 상수(0.8889)로 자동 전환됨 (PL 이 런타임 수신이므로).
