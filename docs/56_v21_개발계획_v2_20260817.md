### ⚠ 베어링 교체에 대한 주의 (문서 54 대조)

54의 증거는 기계보다 **센서 쪽**을 가리킨다 — 잡음이 백색(50 Hz까지 평탄)·정상적이고 **줄 움직임과 무관**해서 "발목축 유격" 후보를 약하게 반박했다. 교체가 나쁠 것은 없고 축을 분해하는 김에 **1순위 후보인 자석 갭·편심을 같이 점검·재장착**하면 한 번에 두 후보를 커버한다. 교체 후 같은 방법(54 §5: 잡고 가진 상태 로그 → 고주파 rms)으로 재측정 — 목표 0.223° → **0.05° 이하**.

## 3. 기능 설계

### A. 상태공간 ↔ 로봇 — 기본 상호작용 (원위치 평면)

- 서버: `sim_engine.set_pose(phi0, alpha0, theta0)` 헬퍼 (reset 의 qpos 부만 분리, qvel=0, mj_forward). `cmd:"pose"` = set_pose + view 브로드캐스트만 (**clear 없음** — 그래프·궤적 보존). hover 진입 `cmd:"pose_begin"` = snapshot() / 이탈 `cmd:"pose_end"` = restore() — 훑기만 하면 원상복귀.
- 클라이언트: `drawPlane()` 이 마지막 스케일 {m, cx, cy, R}을 캔버스별 저장 → 역변환 (CSS px × devicePixelRatio 주의). mousemove 50 ms throttle, **정지 중에만** pose. click = `cmd:"x0"` + `run` (러닝 중 클릭 = 그 자리 즉시 재시작; 리셋 버튼의 같은-판 리플레이 유지).
- 십자선 + (β, φ) + **그 점의 A = wq·(φ,β)** 실시간 표시, 트리거 띠 안/밖 색.
- **스냅 가이드**: Shift = 안정모드선 위로 구속 / Alt = 현재 점을 지나는 수직(불안정) 방향 구속. 서사 4·5 장면 전용 UX.
- 집기 모드 체크박스 (발표 중 오클릭 방지).

### B. 4차원 수동 입력 (예측점 평면의 정확 상태)

- 입력칸 β, φ, β̇, φ̇ + 선택 δ(기본 0). 변환: α = β − P2R·δ, θ = α + δ; δ̇=0 가정으로 α̇ = θ̇ = β̇. (δ≠0 도 이렇게 넣으면 β가 명세대로 유지 — 46 §9 "접힌 자세 던지기" 함정은 α 미보정이 원인, 50 정정 참조)
- 클라이언트가 수신된 PL.P 로 예측점을 미리 그려줌 → "설정" → **x0 확장 명령(속도 포함)** → 물리 시작.
- 서버: `reset()` 에 qvel 세팅 추가. 부호 규약은 qpos 규약(qpos[phi]=−φ, qpos[ankle]=α−qpos[phi], qpos[hip]=θ−α)의 시간미분.
- 검증: 설정 직후 frame 의 plane_pt == 입력 예측점 (기계 정밀도 왕복 일치).

### C. 키네마틱 시연 (물리 정지 상태의 '보여주기' — 이상화임을 라벨로 명시)

- **천천히 접기**: δ 램프 0→X°. CoM 불변 구속으로 상태점이 회색 등고선(기울기 sCoM)을 따라 이동 — 접기 1°당 (Δβ, Δφ) 상수(PL 보유)로 계산해 화면의 회색선과 자기일관. 3D 는 (φ, α=β−P2R·δ, θ=α+δ) 로 동기.
- **F·W·E 시퀀스**: 접기→기다림→펴기 전체 재생 + 단계 라벨. 실물리 대응물은 기존 fwe1/fwe2 모드 (키네마틱 = '이해', 실물리 = '실제').
- 구현: 클라이언트 타이머 → `cmd:"pose"` 스트림 (~20 Hz). 서버 추가 신설 없음.

### D. ε* 장면

예측점 평면의 δ_f* 분홍 화살표에 "ε* 설명" 토글 — A=0 선, CoM 등고선 방향, 교점 작도와 ε* 수치(init 의 eps_star)를 화면에.

### E. 오버랩 — 신규 설계 (match.html 이식안 폐기)

설계 원칙: **정합은 사람 손으로, 수고는 도구가 덜어준다.** 브라우저 내 6점·10미지수 자동 풀이는 실패 이력 — 재시도하지 않는다.

- **E1. 사진/영상 레이어**: `.sim` 영역에 img/video. 두 모드 — **배경**(3D 뒤) / **전경 반투명**(3D 앞). 불투명도 슬라이더, 흑백 토글. 렌더러 alpha:true + 배경 투명 전환.
- **E2. 카메라**: 기존 마우스 조작(회전·팬·줌) 그대로 + **fov·roll 슬라이더 두 개만 추가**.
- **E3. 기하 슬라이더 (v10 복원, 시각 전용)**: 기둥 간격 D·기둥 높이 H. 사람 스케일 범위. **물리는 R·몸 파라미터만 쓰므로 리빌드 없음.** 구현: dispGeom 을 물리 geom 과 분리.
- **E4. 장면 저장**: 카메라+기하+레이어 상태 JSON 을 서버에 저장/불러오기 (`cmd:"scene_save"/"scene_load"`).
- **E5. 연출 애니메이션**: (a) 크로스페이드, (b) **축소 모프** — 정합된 사람 스케일 → 로봇 스케일 (**D 0.60 m**, R 0.433, L1 0.259, L2 0.375) easing 보간. 한 버튼 시퀀스.
- **E6. 자동 정합 지원 (선택 2안)**: (가) **AI 가 대신 정합** — 사진을 세션에 올리면 오프라인 풀이로 장면 JSON 제작 (**8/17 검증 완료**: 축제 실사 1장 → D 11.6 m·zT 2.49 m·재투영 잔차 ~2 px, scene_jultagi.json). (나) 2점 미세 보정 — az·dist·ty 3개만. 전체 자동 풀이는 안 한다.
- 소재: 1차 = 사람 줄타기 사진/영상 (축소 서사), 2차 = 실기 로봇 영상 (실증 대조).

### F. 발표 모드

H = 패널·그래프 숨김, 숫자키 = 카메라 프리셋, 오버레이 글자 확대. **씬 체인은 고정본이 없다** — 문서 49·51 은 참고 초안이며 학생·AI 토의로 발표 대본과 함께 계속 수정된다. 씬 체인은 **순서 교체가 코드 수정 없이 되는 배열 데이터**로 만든다.

### G. 실측 반영

- **실측선 오버레이**: r·절편·λ 입력칸 (λ 기본 5.3) → 두 평면에 별색 실측선 + 실측 트리거 띠, w = [−1/r, 1, −1/(rλ), 1/λ] 병기. β̂ 재구성에는 **P2R 실측 0.417** 명시.
- **실측 발목잡음 프리셋**: 발목 채널 백색 σ 주입 — 기본 0.223° (문서 54), **베어링 교체 후 재측정값으로 갱신**. sim 확장: 엔코더 채널별 σ (`_measure` + real 키).
