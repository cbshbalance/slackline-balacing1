# v22 로거·측정 앱 — 실물 브링업 절차 (2026-09-02)

> 목표: 노트북에 앱을 띄우고 어름이(OpenCR)를 USB 로 붙여 **손으로 움직이면 화면이 따라오는 것**까지 확인한다.
> 그 다음 매달림 영점 → 자유흔들기 → P2R → 놓기 시행을 앱 버튼으로 수행하고 분석 도구로 즉석 검토한다.
> 펌웨어는 **지금 올라가 있는 hangcal_fold 그대로** 시작하고(업로드 없이), 그 다음 `v22_raw` 를 올린다.

## 1. 앱 띄우기 (로봇 없이 먼저 5 분)

```
cd v22_logger
python server.py --fake            ← 합성 신호로 화면 확인
```
브라우저 `http://localhost:8220/`. 3D 로봇이 흔들리고, 두 평면에 금색 궤적, 아래 차트가 흐르면 정상.
- 차트: 휠=줌, 드래그=이동, **Shift+드래그=분석 구간**, 더블클릭=라이브 복귀. Space=재생, ←→=한 칸, M=마크, H=패널 숨김.
- 분석 패널에서 도구 하나(예: 구간 통계) 실행해 결과가 나오는지.
- 끝나면 서버 Ctrl+C. (Windows 에서 한글이 깨져 보여도 동작에는 상관없다 — 서버 출력은 UTF-8 로 고정했다.)

## 2. 기존 펌웨어(hangcal_fold)로 첫 연결 — 업로드 없이

1. **아두이노 시리얼 모니터·hangcal_logger 를 닫는다.** 포트는 한 프로그램만 연다.
2. `python server.py` (가짜 없이) → 브라우저.
3. 헤더의 포트 목록 **↻** → COM 포트 선택(하나면 「포트 자동」 그대로) → **연결**.
   - 콘솔에 부팅 배너가 보이면 좋고, 안 보여도 된다(보드가 이미 돌고 있었던 것).
   - 기록 칩이 `● REC 2026…_auto` 로 바뀐다. 이때부터 `v22_logger/logs/` 에 4파일이 쌓인다.
4. 「명령」탭, 프로파일 `hangcal_fold` 확인 → **m CSV** 버튼 (CSV ON). 콘솔에 `# D,t_ms,phi,ank,…` 헤더와 `D,…` 행이 100 Hz 로 흐르고 헤더 칩에 `… · 100 Hz` 가 뜨면 성공.
   - D행은 오는데 `!! D행이 헤더 없이 온다` 가 뜨면: **m 두 번**(껐다 켜기) → 헤더가 다시 온다.
   - 아무것도 안 오면: 케이블·포트 번호, 다른 프로그램이 포트를 잡고 있는지. 「끊기」→「연결」 재시도.
5. **디지털 트윈 확인**: 로봇을 손으로 움직인다. 3D 로봇이 같은 모양이 되어야 한다. 「데이터」탭 원본값 표와 3D 판독으로 부호 규약을 확인한다 (문서 50 §Z1):
   - 발/줄(크랭크)을 **오른쪽으로 돌리면 phi +**
   - 몸통만 **오른쪽으로 기울이면 ank +**
   - 힙을 접으면 del_now 가 움직이고 θ = α + δ 가 따라온다
   - 반대면 펌웨어 `PHI_SIGN` / `ANK_SIGN` (문서 65 정적 체크 원칙 — 행동 보고 뒤집지 말 것). 그때는 나에게 알려주면 같이 본다.
6. 「데이터」탭 **앱 파생값의 Δ** 를 본다: α·β·φ̇·β̇·Â 의 `펌 …  Δ…`. 정지 상태에서 Δ 가 0 근처면 앱과 펌웨어가 같은 식을 쓰는 것. 속도 Δ 는 0 이 아닐 수 있다(펌웨어는 200 Hz 내부 계산, 앱은 100 Hz 로그 재구성).
7. 마크: 「기록·파일」탭 마크 칸에 `손으로 기울임` → M. 차트에 세로선이 생기고 events.csv 에 남는다.
8. 「끊기」. `logs/` 에 `…_auto.csv / .events.csv / .raw.txt` 가 있는지 확인. 이 첫 파일의 **raw.txt 앞 50줄과 csv 앞 20줄을 나에게 보내 주면** 형식·부호를 같이 검토한다.

## 3. 측정 전용 펌웨어 `v22_raw` 올리기 (선택 — 2 가 되면 언제든)

`v22_logger/firmware/v22_raw/v22_raw.ino` (**v3, 2026-09-05**). 측정(mode 0) + 단일접기(mode 1) + 증분접기(mode 2). 원시값 + 영점 전 14비트 원각 + 서보 tick 을 찍는다.
**여기서는 컴파일을 못 해 봤다** (툴체인 다운로드가 막혀 있다). 호스트 문법검사(`bash firmware/hostcheck/check.sh firmware/v22_raw/v22_raw.ino`)만 통과. 실기 I/O 코드는 incremental_fold_min 에서 그대로다.

v3 에서 바뀐 것 (9/5 실기 관찰로): ① `fphi`/`fank` 직립 변환(아래 4-1) — 없으면 펌웨어 α 가 180° 틀어져 `g` 첫 루프에 FALL. ② **`g` 가 토크를 반드시 켠다** — v2 는 넘어진 뒤에만 켜서, 매달림 영점(토크 OFF) → 세움 → g 순서에서 접기 명령이 허공에 갔다("FOLD 는 찍히는데 로봇은 안 움직임"). ③ FALL 에 α 도 기록(`E,FALLA`). ④ 5 s 마다 `# stat loop_max … dxl_max … dxl_fail … wr_fail …` 계측 한 줄, `t` 에도. **안전장치(무장 유예·폴링 감속·폴링 중단 등)는 넣지 않았다** — 기본 동작을 먼저 본 뒤 하나씩 (사용자 방침 9/5).

1. 아두이노 IDE: 보드 **OpenCR**, 라이브러리 **Dynamixel2Arduino** 설치 확인. 스케치 열고 **컴파일(검증)**. 오류가 나면 **오류 메시지 전체를 나에게** — 바로 고친다.
2. 앱 「끊기」 → 업로드 → 앱 「연결」. 콘솔에 `# v22_raw — …` 배너와 `# D,…` 17열 헤더. 「명령」탭 프로파일을 **v22_raw** 로.
3. CSV 는 기본 ON (100 Hz). 헤더는 20 s 마다 다시 찍히고 `hdr` 로도 받는다. δ 명령은 `E,t,MOVE,값` 을 같이 찍어 P2R 구간 경계가 된다.

## 4. 첫 측정 세션 (앱 버튼으로)

각 항목은 「새 파일」로 이름을 지어 나눈다 (예: `0903_hang_zero`, `0903_swing`, `0903_p2r`, `0903_release`).

### 4-1. 매달림 영점 (문서 66)
- **u 토크해제** → 줄에 완전히 늘어뜨림 → 왼쪽에서 접근해 **완전히 멎으면 z** → 오른쪽에서 접근해 멎으면 **z** (v22_raw: 2단 원형 평균, 콘솔에 데드밴드 표시. hangcal 도 같은 2단).
- 세운다. 원본값 phi 가 ±180 근처면 정상(φ 채널이 도는 것, 문서 66 §4). 앱 「파이프라인」탭 **phi_off = 180** 적용 → u_phi 가 0 근처. (hangcal 은 펌웨어 `fphi 1` 도 가능.)
- 직립에서 u_phi·u_ank·a_alpha 전부 0 근처인지. 이 값이 c₀·φ_eq 의 기준이다 — 재조립하면 다시.
- ★**펌웨어에도 같은 변환을 넣는다**: 콘솔 `fank 1`(발목이 180° 돌아 있을 때), φ 채널도 돌아 있으면 `fphi 1`. 앱의 ank_off/phi_off 는 앱 표시만 바꾸고 펌웨어 α·β·Â 는 못 바꾼다. 확인: 「데이터」탭 alpha 의 `펌 …  Δ…` 가 0 근처. 이걸 빼먹으면 `g` 첫 루프에 `E,FALL`(φ 는 멀쩡, `E,FALLA` 의 α 가 ±180).

### 4-2. 매달림 자유흔들기 (ω_n, ζ, c_φ) — 문서 16 정본과 대조
- 토크 해제로 매달아 φ 4~5° 로 흔들고 손을 뗀다. 20~30 s 기록.
- 차트에서 Shift+드래그로 손 뗀 뒤 구간 선택 → 도구 **감쇠 진동** 실행. ω_n ≈ 4.86 rad/s, ζ ≈ 0.008 (문서 16) 근처인지. 봉우리·영점교차가 차트에 찍힌다.

### 4-3. P2R (문서 64)
- 발목축에서 매달기 → **k 토크ON**(δ=0 재정의) → δ 수동 이동 **0 → 10 → 20 → 30 → 40 → 30 → 20 → 10 → 0**, 각 점에서 살짝 흔들고 **2 s 이상** 멎힐 때까지.
- 도구 **P2R** (구간 나누기 auto: hold 평탄구간 또는 MOVE 이벤트). 결과 0.43 근처·R² 0.9999·구간별 표가 나온다. 「결과 기록」에 남는다.

### 4-4. 놓기 시행 (줄 위, δ 고정) — λ·φ_eq·c₀
- hangcal 이면 **q**(자유비행 모드) **g**; v22_raw 면 그냥 놓는다(제어 없음). 문서 67 놓기 프로토콜, **양방향 섞어서**, 같은 φ 에서 ank ±3° 흩기(c₀).
- 한 시행 뒤: 도구 **시행 나누기**(φ_eq 는 일단 0) → 표에서 방향·λ·유효 여부 → 시행 선택으로 차트가 그 구간으로 → **λ** 실행하면 쓴 점·적합선·2/4/8° 통과시각이 겹친다.
- 10회 넘으면 **φ_eq 훑기**(방향별 λ 곡선의 교점) → 파이프라인 phi_eq 에 넣고 다시 시행 나누기 → 방향 갈림이 20 % 아래로 오는지.
- **놓기 경계** 도구: 놓기점이 원위치 평면에 방향색으로 찍히고 r 고정 절편 c₀ 가 나온다. 다음 시행을 어디에 놓을지(경계에 수직으로 흩기) 평면에서 바로 본다.

### 4-5. g → 삐 → 놓기 (놓기 신호음, 9/5)

"g 직후 바로 놓는다"를 사람 타이밍에 맡기지 않는다. 앱(로거·측정실 왼쪽 위 「놓기 신호음」, 기본 ON)이 D행을 보고 **조건이 0.3 s 유지되면 삐 두 번**을 울리고 3D 창 오른쪽 위에 초록 「● 놓기!」를 띄운다. 그때 놓는다.

- 조건: 목표 십자선이 켜져 있으면 **목표 ±0.2° 도달 + 손 멎음**(|φ̇|,|β̇| < v, 기본 3 °/s). 꺼져 있으면 **|Â| < A**(기본 0.3°) **+ 손 멎음**. 조건이 깨지면 노란 「잡고 멎기 · …」로 이유를 보인다.
- 펌웨어 `E,GO` 가 오면 한 번 더 울린다 — g 를 누른 뒤의 신호가 진짜 신호. 무장(phase 0~2) 전이면 「● 놓기 (비무장 — g 먼저?)」.
- 앱은 판단만 하고 로봇에 아무것도 보내지 않는다.

증분접기 한 회: `mode 2` → 로봇을 세워 잡고 멎음 → **`g`**(토크 ON·무장; 콘솔에 `# 토크 ON`) → 삐 → 놓기 → 관찰 → `h`. FOLD 는 찍히는데 안 움직이면 `t` 의 `dxl_fail`/`wr_fail` 부터.

## 5-1. 발목각(ank)이 안 변할 때 — 코드인지 하드웨어인지 가르는 순서 (9/2 실기 관찰: ank_raw 12000 근처 고정)

코드 검토 결과: v22_raw 의 발목 읽기 경로(CS D9, SPI 모드1 1 MHz, 0xFFFF 두 번 전송 후 두 번째 값 & 0x3FFF)는 hangcal_fold 와
**한 글자도 다르지 않다.** 코드가 잘못됐다면 나타날 신호는 0 또는 16383(레일), φ 와 똑같이 움직이는 값, δ 를 따라가는 값 중 하나다.
"그럴듯한 값(12000)에서 꿈쩍 않음" 은 **센서가 응답은 하는데 자석이 안 돈다** 이거나 **그 채널이 죽어 SPI 버스에 남은 값**을 읽는 것이다.
아래 셋이면 갈린다 (전부 앱 「명령」탭 v22_raw 프로파일 버튼).

1. **기구부터**: 크랭크(발 막대)를 손으로 고정하고 **몸통만** 앞뒤로 기울인다 — 이것이 발목 관절이다. 이때 ank_raw 가 변해야 한다.
   (크랭크째 돌리면 φ 만 변하고, 몸이 크랭크와 같이 돌면 발목은 안 변하는 게 정상이다.)
2. **swap** (CS 핀 교환, 재업로드 없음): 누르고 다시 움직인다.
   - 12000 고정이 **phi 열로 옮겨가고** ank 열이 크랭크를 따라가면 → **D9 채널(커넥터·배선·센서)** 문제. 코드 아님.
   - 그대로면 → 코드/보드 쪽. 그때는 raw.txt 를 나에게.
   - 끝나면 swap 을 한 번 더 눌러 원래대로.
3. **e 엔코더진단**: 콘솔에 두 센서의 `DIAAGC AGC=… MagL MagH COF LF | ERRFL` 과 판독 한 줄이 찍힌다.
   - 전부 0 또는 16383 → 응답 없음 = MISO/CS/전원 커넥터 (문서 52)
   - MagL=1 또는 AGC=255 → 자석이 멀거나 없음 (자석 마운트 빠짐·갭)
   - MagH=1 또는 AGC=0 → 자석이 너무 가까움
   - 정상 응답인데 값이 안 변함 → 자석이 관절과 같이 돌지 않는 기구 문제 (자석 홀더 헛돎, 센서 보드가 관절 반대편에 고정)
   `e` 결과 두 줄을 그대로 보내 주면 판정한다. 8/22 에 발목 센서를 한 번 수리한 이력(문서 64 §7)이 있어 커넥터·자석 쪽이 첫 후보다.

앱은 원본값 표에서 2 s 동안 값이 전혀 안 변한 열을 **빨강 + ⚠고착 2s** 로 표시하고, 펌웨어 err 열에도 등급 2(고착)가 찍힌다.
