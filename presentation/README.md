# presentation/ — 발표 통합 앱 v0.1 (러프컷)

지금까지 만든 시뮬들을 발표 하나로 묶는 앱이다. **서버가 필요 없다** — `index.html` 을 브라우저로 열면 끝.

```
presentation/
  index.html      앱 (감독 레이어 + 3D + 평면 2장 + 조작 UI)
  model.js        (φ, β, δ) 선형 모델 + 궤적 베이커
  three.min.js    v19_state/static 에서 복사
  render.mjs      헤드리스로 프레임을 뽑아 mp4 로 굽는 스크립트
```

---

## 1. 설계 한 줄

> **물리는 앱을 열 때 한 번만 계산(bake)하고, 화면은 그 결과를 시간축으로 훑는다(scrub).**

그래서 **어떤 속도로 재생하든 · 뒤로 감든 · 한 프레임씩 넘기든 항상 같은 그림**이 나온다.
발표 중 아무 데서나 멈추고, 되감고, 1/20 속도로 다시 보여줄 수 있다.

앱이 바깥에 노출하는 계약은 **`window.__seek(t)` 하나**다. 이 함수가 시각 `t` 하나로
카메라·기하·상태·평면·자막·레이아웃을 전부 결정한다(누적 상태 없음).
`render.mjs` 는 실시간 재생 대신 `t = n/fps` 를 직접 넣어 프레임을 뽑는다 —
**발표 앱과 mp4 가 같은 코드에서 나온다.**

## 2. 조작

| 키 | 동작 |
|---|---|
| `Space` | 재생 / 정지 |
| `←` `→` | 한 프레임 (1/60 s) 뒤 / 앞 |
| `Shift` + `←` `→` | 0.5 초 |
| `[` `]` | 이전 / 다음 씬 |
| `1`–`8` | 씬 점프 |
| `0` | 현재 씬 처음으로 |
| `-` `+` | 재생 속도 (0.05× ~ 2×) |
| `V` | 자유 시점 — 마우스 드래그로 회전, 휠로 줌 (**질의응답용**) |
| `H` | UI 숨김 (발표 모드) |
| `?` | 도움말 |

화면 아래 씬 칩을 클릭해도 이동한다. 스크럽 바를 끌면 어디로든 간다.

## 3. 씬 구성 (총 210 s)

| 씬 | 길이 | 내용 | 상태 |
|---|---|---|---|
| ① 역설 | 16 s | 사람 스케일, 넓은 기둥 | **실사 영상 자리** — 지금은 모델만 |
| ② R 하나 | 24 s | 곡률반경 R 추출 → R 0.70→0.433 축소 → 축 방향에서 V자 + D=600 mm | 동작 |
| ③ 평면 | 10 s | xz 평면 등장 → 스윙 평면 정면으로 | 동작 |
| ④ 좌표 | 38 s | φ → α → θ → (β, δ) 갈아타기 | 동작 |
| ⑤ 접기 | 30 s | 완전 사이클을 **118× 느리게** — 접기·대기·펴기 | 동작 |
| ⑥ 평면 2장 | 30 s | 원위치 평면 + 예측점 평면을 3D 와 동기화 | 동작 |
| ⑦ ε*·증분 | 46 s | δ_f* 화살표 · ε* 단일 접기 · 증분 접기 반복 | 동작 |
| ⑧ 실증 | 16 s | 증분 접기 계속 + 제목 카드 | **실기 영상 자리** |

시나리오는 `index.html` 안 `SCENES` 배열이다. **여기 숫자만 고치면 발표가 고쳐진다.**

```js
{ id:'S5', name:'⑤ 접기', dur:30, set:'robot', layout:'3d',
  cam:[[0, V(VIEW.swing,{dist:1.5})], [10, V(VIEW.close)], ...],   // 시각별 카메라
  traj:'cycle', trajT0:0.30, rate:0.0085,   // physT = 0.30 + t_local × 0.0085  ← 슬로우모션 배율
  show:{...}, cap:[[t0, t1, '자막'], ...] }
```

`rate` 가 재생 배율이다. `0.0085` 는 118× 느리게. 접기(60 ms)가 화면에서 7 초가 된다.

`layout`: `'3d'` / `'3d+both'`(3D + 평면 2장) / `'pred+3d'`(예측점 평면 크게 + 3D 작게)

## 4. mp4 굽기

```bash
npm i -g playwright        # 최초 1회 (ffmpeg 도 필요)
node render.mjs                                   # 전체, 1280×720, 24fps
node render.mjs --w 1920 --h 1080 --fps 30        # 본렌더
node render.mjs --from 90 --to 140 --out s6.mp4   # 구간만
node render.mjs --ui                              # 조작 UI 를 켠 채로 (설명 영상용)
```

이 컨테이너 기준 1280×720 / 24fps 전체가 약 6 분.

## 5. 모델 — 어디서 왔고 무엇으로 검산했나

`model.js` 는 `v19_bringup/model_v19.py` 의 JS 이식이다. **파생값 하드코딩 없음** —
파라미터를 주면 M·G·D·μ·모드·λ_u·w·평면 상수를 전부 런타임 계산한다.

파라미터는 `params_v19.py` 의 **`MEASURED_SET`**(2026-07-30~08-06 실측) + `B_THETA = 0`.

### 검산 — `v19_state/README_v19_state.md` 「평면 상수」 빨강(실측) 열과 일치

| 항목 | 이 앱 | v19_state README |
|---|---:|---:|
| λ_u | 5.9219 | 5.9219 |
| A=0 선 기울기 | −1.6451 | −1.6451 |
| CoM 등고선 기울기 | −0.8889 | −0.8889 |
| 접기 1°당 (Δβ, Δφ) | (−0.3517°, +0.3126°) | (−0.3517°, +0.3126°) |

구조 검산 `M_p[φ,δ] = 0`, `G_p[(φ,β),δ] = 0` 도 기계정밀도로 통과(콘솔 출력).
사람 스케일에서는 `ε* = −h/(rR+h)` 공식과 일치(1.437)함을 별도 확인.

### ⚠ 확인 필요 — B_THETA

`v19_state` 의 평면 상수는 **힙 점성감쇠 `B_THETA = 0`** 일 때만 재현된다.
`params_v19.py` 기본값 `B_THETA = 0.01`(미실측 placeholder)로 계산하면
λ_u = **5.8338**, A=0 기울기 = **−1.6648** 로 각각 1.5% / 1.2% 어긋난다.
(문서 42 의 `실측정본 λ_u = 5.813` 은 이쪽 계열이다.)

두 값 중 어느 쪽을 정본으로 쓸지 정해야 한다 — 이 앱은 화면에 나오는 그림이
v19_state 와 같아야 하므로 **0** 을 썼다. `model.js` 의 `SL.PARAMS.robot_meas.B_THETA` 한 줄.

## 6. 이상화 표시 — 정직하게 남겨둘 것

⑤·⑦ 앞부분의 deadbeat 접기는 **접기 종료 시 불안정 성분을 정확히 0 으로 투영**한다
(`SL.bake(..., {deadbeat:'exact'})`). 이론이 말하는 "안정모드 정렬"을 그림으로 보이기 위해서다.

이 투영이 없으면 λ_u = 5.92 /s 아래에서 **수치 잔차가 6 초에 e^{35} ≈ 2.6×10¹⁵ 배로 자라** 반드시
무너진다 — 물리가 아니라 적분 오차다. (γ 는 문서 16 의 원칙대로 **실행 눈금(bake dt)에서 다시 잰다.**
이것만으로도 잔차가 크게 줄지만, 6 초를 견디지는 못한다.)

**⑦ 뒤쪽의 증분 접기(`incr`)에는 투영이 없다** — 실기에 해당하는 정직한 궤적이다.
τ_return = 1.5 s, ρ = 0.9, 트리거 0.6°, 24 초 동안 |A|max ≈ 3.3°, |β|max ≈ 1.2°, 접기 46 회.
