# v19_state — v19_sim + 상태공간 평면 2개

`v19_sim` 을 그대로 복사한 뒤 **화면에 평면 두 개만 추가**한 판.
v19_sim 은 건드리지 않았다. 포트가 달라(8200) 둘을 동시에 띄울 수 있다.

## 실행
```
cd v19_state
python server.py          (또는 run_v19sim.bat)
http://localhost:8200
```

## 추가된 것

### 화면 — 3D/그래프와 오른쪽 패널 사이에 평면 2개

1. **원위치 평면 (β, φ)** — "그림자"
   - 초록 파선 = 안정모드선 `φ = r·β` (무감쇠)
   - 회색 평행선 = CoM 등고선 (접기가 상태를 미는 방향), 기울기 `−s`
   - 흰 점 + 회색 궤적 = **시뮬 참상태** (추정상태는 헷갈려서 안 그린다)
   - 여기서 선 위에 있어도 안정이 아니다 — 속도가 안 보이기 때문(문서 03 §5)

2. **예측점 평면 (β_pred, φ_pred)** — "판정"
   - 초록 실선 = **A=0 판정선** `φ_pred = slopeA0 · β_pred`
     (무감쇠 r 이 아니라 감쇠 포함 좌고유벡터 w_q 에서 나온 선 — 문서 43 ②)
   - **노란 파선 2개 = 트리거 라인 `A = ±A_trig`** — 판정선과 나란하고 절편이 `±A_trig/w_φ`.
     두 선 사이(옅은 노란 띠)가 **무개입 영역**이다. 점이 띠를 벗어나면 증분이 나간다.
     패널의 "A 트리거" 슬라이더를 움직이면 띠 폭이 실시간으로 따라온다.
   - **분홍 화살표 = δ_f\*** — 지금 A=0 으로 보내려면 얼마나 접어야 하는가.
     `δ_f* = −A / (k·(w_φ·s − w_β))` — 문서 41 의 닫힌형. 화살표 길이가 곧 접기량이다.
   - 접기 중(FOLD)이면 점이 분홍으로 바뀐다

   축 범위는 **85 백분위 기준**이다. 접기 순간의 β̇ 스파이크가 스케일을 다 먹으면
   트리거 띠가 안 보이기 때문. 띠가 항상 화면의 1/3 이하로 보이도록 하한도 걸어뒀다.

### 예측점의 정의 (감쇠 일반형)
```
q = (φ, β),   q_pred = q + P·q̇,   P = (λI − D̂)⁻¹
A = w_q · q_pred          (frame 의 A 와 일치 — 검산용)
```
`D̂ = 0` 이면 기존 `q + q̇/λ` 로 환원된다.

## 실기 파이프라인 정합 — 2026-08-14 도입, 08-15 정정

시뮬의 발목엔코더 추정기와 실기 펌웨어(`fwe_async_v19.ino`)는 **A 를 만드는 식이 똑같다**
(α=ank+φ, θ=α+δ, β=P1R·α+P2R·θ, A=w·[φ,β,φ̇,β̇]). 다른 것은 **셋**이다.

| | 시뮬 기본 | **실기 펌웨어** |
|---|---|---|
| 제어주기 | 500 Hz (DT 2 ms) | **200 Hz (dt 5 ms)** |
| 속도 기저차분 | 2 ms (1스텝) | **25 ms (5스텝)** |
| 속도 EMA | τ ≈ 10 ms | **τ ≈ 28 ms** (0.85/0.15) |

### ⚠ 셋은 반드시 함께 바꾼다

500 Hz 에 25 ms 차분만 얹으면 **13스텝 차분**이 되어 실기에도 시뮬에도 없는 **잡종**이 된다.
그 잡종에서만 늦은트리거(|A참| 1.51°)·과접기(19°)·힙 가동률 95% 가 나타나는데,
이것을 실기 현상으로 오인해 T_REST 를 75 ms 로 올리는 잘못된 대책까지 갔다 왔다(둘 다 철회).

**UI 토글**: 「현실화 (플랜트)」 맨 위 **★ 실기 파이프라인** 체크박스가 셋을 함께 전환한다.
**기본 켜짐**이고, 빨간 버튼도 켜진 상태로 시작한다.
코드로는 `real["enc_diff_ms"]=25.0`, `real["enc_tau_v"]=0.030`, `nominal["DT"]=0.005`.

### 펴기 조건은 현행이 맞다 (60 s, 초기조건 4종, 200 Hz)

게이트를 문턱(0.6°) 이상으로 두면 게이트가 없는 것과 같다 — if/elif 구조 때문이다.
그래서 선택지는 **0.3°(현행) 아니면 게이트 없음** 둘뿐이다.

| | 접기 | φ스윙 rms | \|유지각\|최대 |
|---|---:|---:|---:|
| **현행 0.3° · 3°/s** | 181 | **1.13°** | 8.43° |
| 게이트 없음 · 3°/s | 134 | **1.87°** | 8.89° |

**게이트를 없애면 스윙이 커진다.** 펴기 자체가 불안정 성분을 주입하기 때문이다.
유지각 누적도 없다(최대 8.4°, 기구한계 55° 근처에도 안 감).

### 추정점 표시 (2026-08-14)

두 평면에 **추정 상태**(`x̂`, 추정기가 만든 값)를 함께 그린다. 서버는 이미 `plh` 로 보내고 있었고
그리기만 빠져 있었다.

| 요소 | 뜻 |
|---|---|
| 회색 꼬리 · 흰/분홍 점 | **참값** (MuJoCo 실제 상태) |
| 하늘색 점선 꼬리 · **하늘색 링** | **추정값** — 로봇이 실제로 보는 것 |
| 둘을 잇는 가는 선 | 그 순간의 추정오차 |

**중요**: 접기 판정은 **링**이 노란 띠를 넘을 때 일어난다. 점이 아니다.
`추정점 표시` 체크박스로 끌 수 있다. 추정기를 「참값」으로 두면 링과 점이 정확히 겹친다(자기점검).

### 측정할 때 밟았던 함정

- **A 는 `control_step` 이전 값으로 볼 것.** 접기가 시작되면 δ 가 곧바로 β 를 바꿔
  A 가 한 스텝만에 떨어진다. 이후 값으로 보면 전부 헛트리거로 오판된다.
- **'힙 가동률'을 `phase != IDLE` 로 세지 말 것.** REST 대기가 포함돼 모터 활동을 과대평가한다.
- **단발 외란 시험으로 순위를 매기지 말 것.** 킥이 접기 사이클의 어느 위상에 떨어지느냐에
  좌우돼 비단조적 결과가 나온다.
- **g 를 잴 때 모든 Δδ 에 같은 관측창을 쓸 것.** 창이 다르면 G = e^{λT} 가 섞인다.
- **σ_A 잡음 바닥은 가진이 있는 상태에서 잴 것.** 정지 상태에서는 항상 0 이 나온다.

> 증분접기에 실제로 필요한 실측이 무엇인지는 **문서 46** 참조 (P2R / 안정모드선 r·절편 / λ, 그리고 노브 하나).
